    2. 规格化浮点数：阶码不为全0和全1，尾数最高位恒为1
        1. 规格化浮点数的小数点前隐含一个1(隐含位)，**所以23bit实际可以存储24位的尾数**，23bit存小数点后的位，不足则末尾补0：**需要通过移位和改阶，确保小数点前有且仅有一个1**
        2. 单精度浮点数：可表示的阶的范围为：$-126\to 127$，偏置值为$127$($2^{n-1}-1$)
        3. 双精度浮点数：可表示的阶的范围为：$-1022\to 1023$，偏置值为$1023$
        4. 阶转阶码(移码)的方法：阶+偏置值，然后用无符号数编出来

    3. 特殊的浮点数：阶码为全0或全1，按尾数不同再区分
        1. 无穷大：阶码全1，尾数全0。正无穷大于所有有限数。引入无穷使程序在溢出等异常情况下仍然能继续运行
        2. 非数：阶码全1，尾数非0。一个没有定义的数
        3. 零：阶码全0，尾数全0。+0和-0通常是等效的
        4. 非规格化数：阶码全0，尾数非0，不使用隐含位机制(**无隐含的1**)。**此时阶码的真值固定解读为规格化数的最小阶(-126、-1022)，而不是按减去偏置值来算**。用于实现渐进下溢

3. 浮点数的加减运算
    1. 计算方法(五步走)：对阶开始前**注意将隐藏位的1还原**
        1. 对阶：对齐小数点使阶码相等，对阶时进行移码减法运算。**小阶向大阶靠齐**，这样加减之后更容易得到规格化的尾数。**对阶时，至少保留3位冗余位**
            1. 如果大阶向小阶靠齐，如$1.01\times2^{5}\to10.1\times2^{4}$，可以看到小数点前已经有两位，那么加减之后必然不是规格化的尾数
            2. 如果大阶向小阶靠齐，还可能因为移出最高有效位导致精度丢失(小靠大也会丢失精度，不过末尾的位不如开头的位重要，因为位置越靠右，权值越低)
        2. 尾数加减：尾数本身是原码表示，计算机先将其转化成补码，完成补码加减后再转回原码保存。对阶过程中保留的冗余位也要参与运算
        3. 尾数规格化：左规即尾数相对于小数点左移，阶码减少；右规即尾数相对于小数点右移，阶码增加，右规最多进行一次
            ![[Pasted image 20260726155237.png]]
        4. 舍入方式：对阶时保留三个冗余位，供舍入使用。考试默认**就近舍入**(选择最接近真实值的可表示数)，即基于除24位尾数之外的**三位冗余位**进行判断，如果是$0XX$，则直接舍去；如果是$100$，则再看最后一位尾数，尾数为1则进1；尾数为0则直接舍去；其他情况直接进1
            ![[Pasted image 20260726152013.png]]
            ![[Pasted image 20260726155459.png]]
        5. 溢出判断：如果尾数规格化(右规)后阶码为全1，则发生上溢，此时直接将尾数保存为全0，并将结果记作无穷大；如果尾数规格化时，当前阶码已为1，仍需左规(使阶码减小)，则发生下溢，此时直接将阶码保存为全0，尾数不动
            ![[Pasted image 20260726153702.png]]
            ![[Pasted image 20260726213914.png]]

    3. 强制类型转换
        1. C语言支持强制类型转换：`TYPE b=(TYPE)a`. 把a强制转换为TYPE类型，然后赋值给b
        2. 转换过程中，若涉及字长变化，则可能发生**位截断**和**位扩展**
            1. 位截断：长类型转短类型，**系统直接丢弃高位**，仅保留低位。**此类转换不会引起异常或错误**，但是会导致语义变化(转换之后的值与预期值不同)
            2. 位扩展：短类型转长类型，**系统填充高位**。**源数据为有符号数，则做符号扩展；源数据为无符号数，则零扩展**

5. 数据的宽度和存储
    1. 宽度单位
        1. 比特：最小的信息单位，表示一个二进制位
        2. 字节：基本的存储和寻址单位，1字节=8比特
        3. 字：常用的数据组织单位，长度因架构而异，只是一个约定
        4. 机器字长(字长)：即CPU一次能处理的定点整数位数，通常等于CPU通用寄存器的位数和定点运算数据通路宽度，它体现了硬件的实际处理能力
    2. 大小端存储方式：管数据怎么存
        1. 最低有效字节(LSB)表示数据的最低位，最高有效字节(MSB)表示数据的最高位
        2. 给一个十六进制数(比如某地址里存的值)，则左边就是MSB，右边LSB
        3. 大端：低地址存MSB，字节顺序与数值的标准十六进制书写顺序一致
        4. 小端：低地址存LSB，字节顺序与标准书写顺序相反
        ![[Pasted image 20260726161720.png]]
    3. 边界对齐存储：要求数据的存储地址是其对齐值的整数倍(通常为类型大小：字节)
        1. 地址单元从0开始编号，数据的存储地址视为该数据占用的首个地址单元编号
        2. 32位机**对齐**：字节可位于任意地址，半字地址需为2的整数，字地址需为4的整数
        3. **一次访存 = 读一整"行"**，对齐时需要读的行数往往比不对齐少，所以更快
        4. 字长决定了**行长**，即每行的存储单元个数，考试默认32位字长
        5. 精简指令集计算机(RISC)普遍采用边界对齐，以支持高效的指令流水线
        6. C语言struct对齐：注意需要填充整个结构体的大小至满足对齐要求
