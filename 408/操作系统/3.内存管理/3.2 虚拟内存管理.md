# 1.知识点
1. 虚拟内存的基本概念
    1. 传统存储管理方式的特征：一次性、驻留性
        1. 许多在程序运行过程中暂时不用的代码和数据仍需要占据大量内存空间，而一些紧急作业却因为内存不足而无法装入运行，造成了内存的浪费
        ![[Pasted image 20260701142634.png]]
    2. 局部性原理
        1. 从广义上讲，快表、页高速缓存及虚拟内存技术都属于缓存技术，而缓存技术依赖于局部性原理
        2. 时间局部性：同一个数据大概率被多次访问，所以它所在的页也会被重复访问
        3. 空间局部性：连续存储的数据(如数组元素)通常共享一个页，对应的存储单元通常会被连续访问，导致这个页被多次访问
        ![[Pasted image 20260701144011.png]]
        ![[Pasted image 20260629112314.png]]
    3. 虚拟存储器(内存)的定义、特征和实现
        1. 三种机制(对用户透明)：部分装入、请求调页、页面置换
            1. 部分装入：在程序装入时，仅需将当前运行所需的少数页面(段)装入内存，其余部分暂留外存，即可启动程序执行
            2. 请求调页(段)：在程序执行过程中，若所访问的信息不在内存中，则OS会自动将其从外存调入内存，然后继续执行程序
            3. 页面置换(段置换)：内存空间不足时，OS会将暂时不用的信息换出到外存，以腾出空间存放即将调入的内容
        2. 定义：通过请求调页机制和页面置换机制的协同工作，系统为用户提供了一个逻辑上远大于物理内存的地址空间，称为虚拟存储器
            ![[Pasted image 20260701145541.png]]
            ![[Pasted image 20260702085708.png]]
        3. 特征：多次性、对换性、虚拟性
            ![[Pasted image 20260701145713.png]]
        4. 虚拟内存的实现建立在**离散分配的内存管理方式**基础之上
            ![[Pasted image 20260701152207.png]]
2. 请求分页管理方式
    1. 请求分页 VS 基本分页
        1. 请求分页有请求调页和页面置换功能，而基本分页无
        2. 请求分页系统中，对换的基本单位是长度固定的页面，而不是长度可变的段。故请求分页系统比请求分段系统更容易实现，是目前最常用的一种虚拟存储器实现方式
        ![[Pasted image 20260701153028.png]]
    2. 页表机制
        1. 支持请求调页：需要知道目标页是否已在内存(状态位)；如果不在，那在外存中的哪个位置(外存地址)
        2. 支持页面置换：记录访问特征以作为置换参考(访问字段)；换出时判断是否需要写回外存(修改位)(没修改过就没必要额外写一次)
        ![[Pasted image 20260701154021.png]]
        ![[Pasted image 20260701154030.png]]
    3. 缺页中断机构
        1. 处理流程
            1. 进程访问的页不在内存中时，硬件会触发缺页中断。OS的缺页中断处理程序负责将所需页面从外存调入内存
            2. 若内存中有空闲页框，则直接把缺页装进去，并更新页表；若无，则使用页面置换算法淘汰一个页面(脏页需写回)，把缺页装进这个页框里
            3. 引发缺页的进程阻塞，直至调页完成再加入就绪队列。调页涉及较长时间的IO操作，这段时间内OS会调度其他进程运行
            4. 缺页中断处理完成后，应重新执行引起中断的那条指令

3. 页框分配
    1. 最小页框数：能保证进程正常运行所需的最少页框数，取决于**计算机的硬件结构：指令的格式与功能、寻址方式**(学完计组再看)
        ![[Pasted image 20260701190857.png]]
    2. 驻留集：指在某一时刻，进程实际已经调入物理内存的页面的集合。驻留集的元素本质上是**页号**
        1. 驻留集大小：权衡**系统并发度**与**缺页开销**后决定
        ![[Pasted image 20260701191404.png]]
    3. 页框分配与置换策略(两两组合，得到三种)
        ![[Pasted image 20260701192744.png]]
        1. 分配策略：固定分配和可变分配
            1. 固定分配：为每个进程分配固定数量的页框，并在其运行期间保持不变
            2. 可变分配：初始时为每个进程分配一定数量的页框，并在运行期间根据需要动态调整，驻留集大小可变
        2. 置换策略：全局置换和局部置换
            1. 局部置换：进程缺页时，只能从该进程自身已分配的页框中选一页换出，从而保持驻留集大小恒定
            2. 全局置换：进程缺页时，OS选一个空闲页框或者换出任意一页(这一页可能是当前进程的)，以腾出空页框给当前进程
        3. 固定分配局部置换：难以确定分配多少个页框。太多浪费内存，太少频繁缺页
            ![[Pasted image 20260701195701.png]]
        4. 可变分配全局置换：比上一种更灵活，能更好地满足进程需求。可能导致某些活跃进程的驻留集持续膨胀，而被抢占页框的进程缺页率上升，降低系统并发能力
        5. 可变分配局部置换：既能有效抑制进程频繁调页，又兼顾了系统的并发能力。虽然运行开销较大，但是能够降低IO开销，提升CPU利用率
    4. 页框调入算法：采用固定分配策略时，如何给进程分配空闲页框
        ![[Pasted image 20260701200912.png]]
    5. 页面调入时机：预调页(进程首次调入时、运行前)、请求调页(进程运行期间)
        ![[Pasted image 20260701201058.png]]
    6. 从何处调入页面(三种情况)
        1. 请求分页系统中的外存分为文件区和对换区(交换区)：文件区采用离散分配方式，用于存放文件；对换区采用连续分配方式，用于存放换出页面。对换区的磁盘IO速度通常更快
        2. 情况一：系统拥有足够的对换区空间
            1. 全部在对换区进行调入调出，效率最高
            ![[Pasted image 20260701201932.png]]
        3. 情况二：系统对换区空间不足
            1. 不会修改的数据从文件区调入，调出时无需写磁盘；可能修改的在对换区调入调出，兼顾效率与正确性
            ![[Pasted image 20260701202054.png]]
            ![[Pasted image 20260701202106.png]]
        4. 情况三：UNIX方式
            1. 第一次调入从文件区，再次调入调出都从对换区

    7. 抖动和工作集
        1. 抖动(颠簸)：刚刚换出的页面马上又要换入内存，而刚刚换入的页面又立即被换出。这种频繁的页面调度行为称为抖动
            ![[Pasted image 20260701203911.png]]
        2. 工作集：用于动态指导页框分配，驻留集的大小不应小于工作集的大小
            1. 局部性较好的程序，其工作集大小一般远小于窗口尺寸
            2. 选定t时刻，往前包含一共$\Delta$个页，即为工作集

4. 页面置换算法：缺页且内存不足时，如何选择被换出(淘汰)的页
    1. 算法目标是**降低缺页率**：页面的换入换出均涉及磁盘IO，开销大。缺页率低，则对换少，系统性能更好
        ![[Pasted image 20260701185520.png]]
        ![[Pasted image 20260702101320.png]]
    2. 最佳算法(OPT)：选择淘汰**以后永不使用**或者**在最长时间内不再被使用**的页面
        1. 由于OS无法预知未来的页面访问序列，故该算法无法实现，仅作为最优情况和其他算法对照，以比较性能
        ![[Pasted image 20260701165537.png]]
    3. 先进先出算法(FIFO)：选择淘汰**最早进入内存**的页面
        1. 将内存中的页面按调入时间组织成一个队列，换出时淘汰队头页面。队列最大长度为系统给进程分配的内存块数
        2. 实现简单，但未利用局部性原理，性能通常较差
        3. 唯一会出现**Belady异常**的置换算法：分配内存块变多，反而缺页次数变多
        ![[Pasted image 20260701170247.png]]
        ![[Pasted image 20260701170259.png]]
    4. 最近最久未使用算法(LRU)：选择淘汰**最近最长时间没使用**的页面
        1. 若页面在过去一段时间内未使用，则在邻近的未来很可能也不会被访问
        2. 系统为每个页面维护一个访问字段，记录**距其上次被访问所经历的时间**，每次淘汰这个值最大的
        3. 性能接近OPT，但实现需要硬件支持，开销较大
        4. LRU看"过去"，而OPT才能看见"未来"
    5. 时钟算法(CLOCK)(最近未用算法)(NRU)：性能和开销较均衡的算法
        1. 简单的CLOCK算法
            1. 为每个页面设置一个访问位，页面**被装入或访问时**，访问位改为1
            2. 所有页框组织成**循环队列**，并维护一个**替换指针**，指向当前检查位置(即考虑换出的位置)
            3. 发生缺页时，从替换指针位置开始检查。若所指位置访问位为0，则淘汰该页；否则，将该页的访问位置为0，指针指向下一个页面并检查
            4. **最多进行两轮扫描，即可完成淘汰**
            5. 没给指针方向，默认顺时针
            ![[Pasted image 20260701172421.png]]
        2. 改进型CLOCK算法
            1. 修改过的页面需要写回磁盘，置换代价更高。为降低IO开销，在简单CLOCK算法的基础上，改进CLOCK算法引入了修改位M，**综合考虑页面的使用情况与置换代价**，淘汰时优先选择既未被访问过，又未被修改的页面
            2. 各类页面淘汰优先级如下(先考虑访问与否，再考虑修改与否)
                ![[Pasted image 20260701184610.png]]
            3. 优先淘汰未修改的页面，从而降低磁盘IO开销，优于简单CLOCK；但扫描轮数增多，算法开销变大
            4. **最多进行四轮扫描，即可完成淘汰**
            ![[Pasted image 20260701185006.png]]

6. 内存映射文件(MMF)
    1. 内存映射文件，是OS向应用程序提供的**一种系统调用**机制——将磁盘上某个文件的内容，通过**页表建立映射关系**，直接映射到进程的一段**虚拟地址空间**里，使得进程可以像**访问普通内存数组**一样，用指针/下标去读写这个文件，而不需要走传统的`read()`/`write()`系统调用
        ![[Pasted image 20260701220238.png]]
        ![[Pasted image 20260701220328.png]]
    2. 文件内容的实际调入调出，由OS通过请求分页机制完成，对进程来说是透明的
    3. 映射时不会立即加载文件内容，而是按需调入；当进程退出或显式解除文件映射时，脏页才会写回磁盘
    4. 共享内存往往是通过将同一文件映射到多个通信进程的虚拟地址空间来实现的。OS通过页表将这些进程的虚拟页映射到相同的物理页，A进程修改的结果B进程可以立刻看到(同一块物理内存)，使不同进程之间可以高效通信

7. 虚拟存储器性能影响因素：缺页率
    1. 由空间局部性得：**页面较大时**，顺序访问的数据/指令位于同一页，从而**降低缺页率**；**页面较小时**，要访问的数据位于不同页，**缺页率则相对较高**。页面大小设计还要考虑碎片和页表开销：页面小，碎片少，内存利用率高；但页数多，页表开销大
    2. 分配的块数越多，缺页率通常越低。但**块数超过某个阈值时**，再增加块数，**缺页率会保持平稳**，因为进程的活跃页面都已常驻内存。此时再分配更多块，反而会浪费内存。因此，只需**确保活跃页面常驻内存**，即可将缺页率控制在可接受范围
        ![[Pasted image 20260701222102.png]]
    3. 好的页面置换算法可以有效降低缺页率
    4. 程序编写的局部化程度越高，缺页率就越低
        ![[Pasted image 20260701222546.png]]
    5. 批量写脏页：降低IO次数和换入频率(严格来说不属于影响缺页率，教材挂这)
