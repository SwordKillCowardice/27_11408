# 1.知识点
1. 前置知识
    1. 内存(主存)：用于存放当前正在执行的程序及其数据
    2. 内存编址：区分地址的最小单位，即一个存储单元的大小
        1. 题干说按字编址时，需要注意字长
        ![[Pasted image 20260626163938.png]]
    3. 指令地址：指的是某个进程的可执行代码(指令本身)在内存中存放的逻辑地址
    4. **程序执行前必须先将其装入内存**：因为CPU不能直接对外存(如磁盘)进行寻址访问。此外，由于CPU的工作速度远高于外存的访问速度，若直接进行数据交换，会导致CPU长时间处于等待状态，造成资源的极大浪费，这也是引入**存储器层次结构**(缓存—主存—外存)的核心动机之一
    5. **逻辑地址 VS 物理地址**
        1. 逻辑地址(相对地址、虚拟地址)：源程序经编译后形成若干目标模块，每个目标模块都从0号单元开始编址；经链接器链接后，**各模块**地址被统一组织为一个**从0开始、连续编址**的完整地址空间，这就是该程序的**逻辑地址空间**
            1. CPU执行时所访问的地址即为逻辑地址(**进程运行时所使用的地址均为逻辑地址**)，需通过地址变换(静态重定位或动态重定位)转换为物理地址后，才能实际访问主存
            2. 不同进程可以拥有相同的逻辑地址
        2. 物理地址(绝对地址)空间：主存中各物理存储单元所对应的地址值的全体集合，是**地址转换的最终目标**。主存作为硬件设备，只能依据物理地址完成实际的读写操作
        3. 逻辑地址转化为物理地址的过程，称为地址重定位。在现代支持虚拟内存的系统中，该转换由内存管理单元(MMU)在硬件层面于运行时自动完成
    6. 从写程序到程序运行：编辑->编译->链接->装入->运行
        ![[Pasted image 20260626165508.png]]
        ![[Pasted image 20260626171807.png]]
    7. **程序的装入**：将装入模块载入内存，同时实现地址转换
        1. 绝对装入：**仅适用于单道程序环境**。由于内存中只运行一个程序，**程序将被装入的内存起始位置可以提前确定**。据此，程序中使用的**地址**可以在**编译阶段**就直接**转换为绝对地址**(通常情况)，也可以由程序员手工写入绝对地址。链接阶段只需将各模块(已是绝对地址)拼接成完整的装入模块，装入内存时无需再做任何地址变换，直接按地址原样存放即可
            ![[Pasted image 20260626170908.png]]
        2. 可重定位装入(静态重定位)：在多道程序环境下，由于无法预知目标模块在内存中的具体位置，装入模块在装入前使用的是逻辑地址。系统为该模块分配一块**连续**的内存区域，并将**整个**模块一次性装入(即**进程在装入前必须一次性获得其运行所需的全部内存空间**)。**装入时**，由装入程序根据所分配的起始地址，**一次性把模块中的逻辑地址全部转换为物理地址**，这一过程称为**静态重定位**。转换完成后，地址在程序运行期间**不再改变**，因此进程一旦装入就**不能在内存中移动位置**，也**不能在运行期间动态申请额外的内存空间**——这正是静态重定位灵活性差的根本原因
            ![[Pasted image 20260626171649.png]]
        3. 动态运行时装入(动态重定位)：装入程序将装入模块载入内存后，并不立即转换地址，而是把地址转换推迟到**指令实际执行时**才进行。为此需引入一个**重定位寄存器**，存放该模块在内存中的起始物理地址。**地址变换公式为：物理地址=逻辑地址+重定位寄存器的值**，且**这个加法在程序运行期间，每次访存都要重新计算一次**。装入模块和存储空间里始终保留逻辑地址，正因为指令本身从未被改写，所以该进程才能够**在内存中被任意移动**——只需更新重定位寄存器的值即可，不必触碰指令内容这一特性带来两个重要好处：
            1. 当内存中出现大量分散的外部碎片时，操作系统可以通过**紧凑**，把若干运行中的进程整体移动、腾出连续空闲区，从而有效减少外部碎片
            2. 允许进程在运行期间根据需要**动态申请额外内存**、灵活调整自身的内存布局，甚至在原位置空间不足时被整体迁移到内存中更大的空闲区
            ![[Pasted image 20260626172052.png]]
    8. 程序的链接：生成装入模块(考察频率不高)
        1. 静态链接：在程序运行之前，由链接器将编译生成的各个目标模块，以及程序中所调用的库函数模块，链接装配成一个完整的装入模块(即可执行文件)，此后整体不再拆分，作为一个统一的单元被装入内存运行。链接过程中需要完成两项关键工作：
            1. 地址调整：模块2本来从0开始。链接时，模块2的所有内部逻辑地址均要加上模块1的大小99
            2. 外部符号解析：将模块间引用的外部符号(如函数名)替换为确定的地址
            ![[Pasted image 20260626172753.png]]
        2. 装入时动态链接：**在装入时，边装入边链接**。具体而言，装入程序在装入主模块的过程中，每当遇到一处对外部模块的引用，就随即转去查找该外部模块、将其装入内存，并将调用处的外部符号替换为正确的地址
            ![[Pasted image 20260626173320.png]]
        3. 运行时动态链接：链接的时机被推迟到**程序执行过程中、真正执行到调用指令的那一刻**才进行。换言之，对于那些本次运行**可能根本不会被执行到**的模块，由于程序执行始终没有走到对应的调用语句，这些模块便**完全不会被装入内存、也不会被链接**。这种"按需懒加载"的特性，既减少了装入阶段需要处理的模块数量，从而**加快了程序的装入过程**；也避免了用不到的模块占据内存空间，从而**节省了内存空间**

2. 内存管理的概念

3. 连续分配管理方式：为用户进程分配的必须是一个**连续的内存空间**
    1. 内部碎片：分配给某进程的内存区域中，未被利用的部分
    2. 外部碎片：散布在已分配分区之间，无法利用的小空闲块
    3. 单一连续分配：内存被划分为系统区和用户区。系统区仅供OS使用，常位于低地址部分，用户区则**仅允许一道用户程序进行**，该程序独占整个用户区
        1. 无须内存保护：内存中始终只有一道程序，即使该程序错误地修改了系统区数据，通常重启电脑即可
        ![[Pasted image 20260626211600.png]]
        ![[Pasted image 20260626211252.png]]
    4. 固定分区分配：将用户内存空间划分为若干**大小固定的分区**，系统启动时**一次性、永久**划定。每个分区仅装一个进程。是**最简单的多道程序存储管理**方式
        1. 两种分区划分方式：分区大小相等、分区大小不等
            ![[Pasted image 20260626212211.png]]
            ![[Pasted image 20260626212428.png]]
            ![[Pasted image 20260626212259.png]]
        2. 系统维护一张分区使用表，来实现各分区的分配与回收，通常按分区大小排列。每个表项包含对应分区的起始地址、大小和状态
            ![[Pasted image 20260626212903.png]]
        3. 优点是实现简单，无外部碎片    
        ![[Pasted image 20260626213438.png]]
    5. 动态分区分配(可变分区分配)：不会预先划分内存分区，而是在进程装入内存时，根据进程的大小动态地建立分区，并使分区的大小正好适合进程的需要。因此系统中分区的数量和大小随进程的装入与释放动态变化
        1. 系统维护一张(条)空闲分区表(链)，通常按起始地址排序
            ![[Pasted image 20260626215107.png]]
        2. 把一个新作业装入内存时，需按照一定的动态分区分配算法，从空闲分区表(链)中选出一个分区分配给该作业
        3. 分配与回收过程
            1. 分配完成后，从空闲分区表中删除对应分区；或修改对应分区的起始地址和大小
                ![[Pasted image 20260626215507.png]]
                ![[Pasted image 20260626215614.png]]
            2. 回收时：相邻的空闲分区要合并
                ![[Pasted image 20260626215834.png]]
                ![[Pasted image 20260626215912.png]]
        4. 动态分区分配**没有内部碎片，但有外部碎片**。可以通过**紧凑技术缓解外部碎片**OS周期性地移动进程，将所有空闲块合并为一个连续区域。该操作**需要OS支持动态重定位**，开销较大
    6. 动态分区分配算法：选择哪个空闲分区分配给作业
        1. 顺序分配(基于顺序搜素的分配)算法：依次遍历空闲分区链，查找第一个满足作业大小要求的分区。注意：空间余下的部分要**分割出来**，留在链表中(产生了难以利用的小块碎片)
            1. 从实现开销，碎片控制与大作业支持来衡量。实现开销主要指**维护空闲分区链**的开销
            2. 首次适应算法(First Fit)：空闲分区**按地址递增次序排列**。分配时从链头开始顺序查找，找到第一个满足请求的空闲分区分给作业
                1. 优先利用低地址分区，**从而保留高地址的大空闲区，有利于后续大作业进入**
                2. 低地址容易积累碎片，且每次分配都要从链头开始找，查找开销大
            3. 最佳适应(Best Fit)：空闲分区**按容量递增次序排列**。顺序查找第一个能满足作业大小的空闲分区进行分配(最小的可用分区)
                1. 能尽量保留较大的空闲分区
                2. 每次分配都会在原分区中留下极小的剩余块，慢慢产生**大量外部碎片**实际性能通常较差
            4. 最坏(大)适应(Worst Fit)：空闲分区**按容量递减次序排列**。与最佳适应相反
                1. 通过避免生成小碎片来提升内存利用率(分配后的空闲区不会太小，就能利用)
                2. 由于总是切割最大的空闲区，系统很快难以满足大作业的内存需求，性能同样不佳
            5. 邻近适应(循环首次适应)(Next Fit)：由首次适应算法改造而来，但空闲分区用循环链表组织。分配时从**上次查找结束的位置**开始继续循环搜索，而非每次都从链头开始
                1. 减少了对低地址区域的重复扫描
                2. 低地址和高地址的空闲分区被使用概率相同，导致高地址的大空闲分区更可能被划分为小分区，难以支持后续大作业使用，性能不如首次适应
            ![[Pasted image 20260627084405.png]]
        2. 索引分配算法(基于索引搜索的分配)(大中型系统)：根据空闲分区的大小进行分类，对每一类大小相同的空闲分区建立独立的空闲分区链，并通过**索引表**统一管理这些链。分配时，根据分区大小在索引表中先找到链头指针，从而**快速定位满足要求的空闲分区(链)**(速度快于顺序分配)
            1. 快速适应(Quick Fit)算法：统计系统中进程**常用**的空间大小(比如16KB)，为每一种大小**单独建一条空闲分区链表**，然后使用索引表控制访问
                1. 查找效率高； **不会产生外部碎片**：整个分区全部分给进程，**而不做切割**，回收时整个一起回收，能保留大分区
                2. 会产生内部碎片
                ![[Pasted image 20260627100253.png]]
                ![[Pasted image 20260627100536.png]]
            2. 伙伴系统：所有分区(已分配+空闲分区)大小均为$2^k$，每种大小单独开一个空闲分区链
                1. 分配规则：首先根据进程大小计算出$I$值，接着看有没有$2^I$大小的空闲分区，有的话直接分配。没有就向上看有没有$2^{I+1}$，有的话把$2^{I+1}$拆成两个，其中一个分给进程，另一个放入空闲链。没有就接续往上找，找到顶之后不断二分，直到满足需求

                3. 伙伴分区：除最大分区(根节点)外，每个大小为$2^k$的分区都**有且仅有一个伙伴分区**：与它大小相同，地址相邻。**这两个分区是从同一个大分区二分得来的**

4. 非连续分配管理方式
    1. 定义：将进程的地址空间划分为多个单元，并允许这些单元分散地装入互不相邻的内存区域
    2. 影响：该机制可以有效利用零散的空闲内存，显著提升内存利用率；但也引入了需要额外维护映射关系的存储开销(如页表、段表)
    3. 根据所划分单元的大小是否固定，可以分为分页存储管理和分段存储管理
    4. 若作业运行前需要一次性装入全部单元，则称为基本分页(分段)；若支持按需动态装入，则称为请求分页(分段)
    ![[Pasted image 20260629165511.png]]
5. 基本分页存储管理
    1. 基本概念
        1. 页面和页框
            1. 将物理内存划分为若干大小相等的固定单元，每个单元称为一个页框(页帧、内存块、物理块、物理页面)，每个页框有一个编号，称为页框号(页帧号、物理块号)
            2. 将进程的逻辑地址空间划分为与页框大小相同的单元，每个单元称为一个页面(页)，每个页面有一个编号，称为页号
            3. 页号和页框号都从0开始
            4. 进程的每个页面分别放入一个页框中，进程的页面与内存的页框一一对应
            5. 页面大小通常取$2$的整数次幂。页面大小应适中：页面太小，会导致进程页数太多，对应页表过长，不仅占用大量内存，还会增加地址转换开销，降低页面换入/换出效率；页面太大，则页内碎片增多，降低内存利用率
            ![[Pasted image 20260627164104.png]]
        2. 页表
            1. OS为每个进程建立一张页表，以实现从页号到页框号的映射
            2. 页表是一个按页号顺序排列的数组，每个页表项记录对应页面所在的物理页框号，以及相关状态信息(如有效位)。进程的每个页面对应一个页表项，每个页表项长度相同。注意：**页号隐含在数组下标中，不用单独存储，不占存储空间**，故计算页表项大小时，只需要计算存储块号所需大小
            3. 页表通常存在PCB中
            4. 利用数组特性定位第$i$个页表项的起始地址
                ![[Pasted image 20260627172302.png]]
                ![[Pasted image 20260627172315.png]]
            5. 页表项大小计算：先求页框(内存块)总数，据此得到最大内存块号，接着求出表示这个块号所需的最小字节数

    4. 具有快表的地址变换机构
        1. 引入原因：使用基本地址变换机构时，若页表全部存储在内存中，则每次访问逻辑地址的内容**至少需要两次访存**：第一次查页表，第二次根据地址找内容。这种方式会降低系统性能
        2. 快表(联想寄存器)(TLB)：一个具有并行查找能力的**高速缓冲存储器**，用于缓存当前**活跃的若干**页表项，以加速地址变换
            1. 相对的，主存中的完整页表称为慢表
            2. 快表属于高速缓存，通常是用**相联存储器**实现的，命名为联想寄存器是从实现角度做的
            3. 快表中只存页表项的副本，而普通Cache中可能有其他各种数据的副本

            3. 快表未命中时，则老实访问两次内存，然后再把页表项加入快表。把该页加入快表的访快表时间**不计入访问逻辑地址的耗时**

            2. 空间局部性：连续存储的数据(如数组元素)通常共享一个页，对应的存储单元通常会被连续访问，导致这个页被多次访问

            2. 由局部性原理知：进程在一段时间内只需要访问某几个页面就可以正常运行，没必要整个页表都常驻内存

    1. 定义
        1. 在用户编程时，按**程序自身的逻辑关系**将用户进程的逻辑地址空间**划分为若干大小不等的段**，每个段都有一个段名。

    6. 分段 VS 分页
        1. 页是系统管理内存的物理单位，分页的主要目的是**提高内存利用率**，完全由系统实现，对用户透明
        2. 段是用户程序的逻辑单位，分段的主要目的是**满足**方便编程、信息共享与保护、动态增长以及动态链接等**用户需求**，由编译器根据程序结构划分，对用户可见
        3. 页的大小固定，由系统决定；段的长度不固定，取决于程序的逻辑结构
        4. 分页的地址空间是一维的，程序员只用提供单一的线性地址；分段的地址空间是二维的，程序员必须同时指定段名(段号)和段内偏移量
        5. 分段比分页更容易实现信息的共享与保护
            1. 原因：因为段是逻辑单位，共享一个段就能共享一整段逻辑代码；而同一段逻辑代码用页共享，就得拆成多个页

            2. 同一共享段在不同进程中可以有不同的段号
                ![[Pasted image 20260629155140.png]]
        6. 段式管理不会产生内部碎片    
        ![[Pasted image 20260704110322.png]]
7. 段页式存储管理
    1. 定义
        1. 分页能有效提高内存利用率；分段能反映程序的逻辑结构，利好共享与保护。将二者各自的优势有机结合，便得到了段页式存储管理方式
        2. 对进程的地址空间先分段，每段段号唯一，随后对每个段再分页
        3. 内存空间管理仍然采用分页方式，即把内存空间划为一个个页。内存分配以物理块为单位
        ![[Pasted image 20260629161222.png]]
    2. 逻辑地址结构
        1. 地址是二维的：程序员编程时给出段号和段内地址即可，对各段的分页由系统完成，对用户不可见
        ![[Pasted image 20260629161856.png]]
    3. 段表
        1. 每个进程都拥有一张段表。由于每个段都对应一张页表，所以一个进程可能有多张页表
        2. 每个段对应一个段表项，记录该段的页表始址(页表存放块号)和页表长度
        3. 每个段也对应一张页表，每个页表项记录对应页的物理块号
        4. 系统设置一个段表寄存器，用于存放当前进程段表的起始地址和段表长度，既用于段表寻址，又用于段号越界检查
        ![[Pasted image 20260629163317.png]]
    4. 地址变换
        1. 不使用快表的话，三次访存
        2. 用快表，若命中则一次访存。表项为：段号、页号、物理块号等
