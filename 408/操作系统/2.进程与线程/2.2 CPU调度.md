# 1.知识点
1. 调度的概念
    1. 定义
        1. 调度：资源有限，多个任务无法同时处理，需要确定某种规则来决定处理这些任务的顺序，这就是调度研究的问题
        2. CPU调度：按照一定的算法(兼具公平性与效率)，从就绪队列中选择一个进程，并将CPU分配给它运行，从而实现多个进程的并发执行
    2. 调度的层次(三级调度)
        1. 示意图
            ![[Pasted image 20260618191349.png]]
        2. 高级调度(作业调度)：把作业变成进程，并完成进程从创建态到就绪态的工作
            1. 按一定的规则从外存的作业后备队列中挑选一个或多个作业调入内存，并创建相应的进程，使其可以参与CPU竞争
            2. 每个作业在整个生命周期中**仅被调入一次、调出一次**。调入时创建PCB，调出时撤销PCB
            3. 传统多道批处理系统普遍配备作业调度。但分时系统以及实时系统中，用户进程通常由交互式命令直接创建，故一般不设置独立的作业调度模块
        3. 中级调度(内存调度)：提高内存利用率和系统吞吐量
            1. 系统内存紧张时，将某些暂时无法运行的进程换出到外存，此时进程变为挂起态，被挂起的进程的PCB会组织成挂起队列；等这些进程具备运行条件且内存有空闲时，再将其换入内存，恢复为就绪态，等待调度
            2. 定义：按照某种策略，决定将内存中哪个暂时不能运行的进程换出，或将哪个挂起进程重新调入内存
            3. 一个进程可能会多次被调入调出，因此中级调度发生的频率比高级调度高
            4. 中级调度一定会增加系统开销
            5. 七状态模型(挂起态可以进一步分为就绪挂起和阻塞挂起)
                ![[Pasted image 20260618193445.png]]
        4. 低级调度(进程调度/处理机调度)：给进程分配处理机
            1. 按照特定算法从就绪队列中选择一个进程，将CPU分配给它
            2. 进程调度是OS中最基础、最频繁的调度，在所有OS中都必须存在
        5. 三级调度的联系与对比
            1. 作业调度和中级调度发生在内外存之间，进程调度则从内存到CPU
            2. 作业调度：进程从无到创建态，再到就绪态
            3. 中级调度：进程从就绪(阻塞)挂起到就绪(阻塞)
            4. 进程调度：进程从就绪态到运行态
            ![[Pasted image 20260618193727.png]]
2. 进程调度
    1. 进程调度任务(三步)：保存原进程现场、选进程、完成CPU分配
        1. 这里指广义的进程调度，后两步即选进程+切换进程
        2. 狭义的进程调度：从就绪队列中选中一个要运行的进程
        ![[Pasted image 20260618195859.png]]
    2. 进程调度的时机
        1. 需要进行进程调度与切换的情况
            1. 补充：创建新进程后，此时父子进程都处于就绪态，此时要选一个来运行
            2. 有的系统中，只允许进程主动放弃处理机
            ![[Pasted image 20260618203834.png]]
        2. 不能进行进程调度与切换的情况
            1. 若在下述不可调度期间发生了调度条件，系统会设置一个**调度请求标志**，等当前处理完成后，再根据该标志进行调度与切换操作
            ![[Pasted image 20260618204130.png]]
            2. 进程在操作系统**内核**程序**临界区中不能**进行调度与切换，但处于**普通临界区可以**。理解：内核临界区中的资源会影响OS管理工作，应该让访问该区域的进程尽快完成操作，然后将资源释放出来(进临界区会加锁)；后者无所谓
            ![[Pasted image 20260618204639.png]]
    3. 进程调度的方式：当某个进程正在CPU上执行时，若有优先级更高的进程进入就绪队列，此时系统如何分配CPU
        ![[Pasted image 20260618205902.png]]
    4. 调度程序(调度器)
        1. 定义：调度器是用于实现CPU调度与分派的软件组件，负责决定让哪个进程或线程运行以及运行多久。调度器是OS内核程序
        2. 组成部分：排队器+分派器+上下文切换器
            1. 排队器：将就绪进程插入相应的就绪队列，为调度做准备
            2. 分派器：将CPU分配给调度算法选定的进程
            3. 上下文切换器：负责执行CPU切换期间上下文(运行现场)的切换操作
        3. 触发调度程序的事件：创建新进程、进程退出、进程阻塞、I/O中断发生(唤醒进程)。本质就是CPU空了，或者就绪队列改变了
            1. 非抢占式调度：运行进程主动放弃CPU才触发调度
            2. 抢占式调度：通过时钟中断，每隔一段时间就检查就绪队列有无优先级更高的进程
            ![[Pasted image 20260618202147.png]]
        4. 调度程序的处理对象：进程(用户级线程调度)或线程(内核级线程调度)
            ![[Pasted image 20260618202547.png]]
    5. 闲逛进程(idle)：没有其他就绪进程时，OS会运行闲逛进程(pid=0)
        1. 闲逛进程负责在空闲循环中不断检测中断请求
        2. 闲逛进程不占用除CPU外的任何系统资源，也不会被阻塞
        ![[Pasted image 20260618202932.png]]
3. 进程切换
    1. 定义：进程切换是指一个进程让出处理机，由另一个进程占用处理机的过程。这个过程中要进行上下文切换
    2. 上下文切换：保存当前进程的状态，恢复另一个进程的状态(通过PCB)
        1. 上下文切换是一项开销较大的操作
        2. 模式切换 VS 上下文切换
            1. **模式切换发生在同一进程内部**。在此**过程中**，当前进程不改变，故**不需要进行上下文切换**
            2. **上下文切换**意味着从一个进程切换到另一个进程，该操作涉及PCB的访问与修改，**只能由内核完成，整个切换过程运行在内核态**
        ![[Pasted image 20260618213530.png]]
    3. 过于频繁地进行进程调度、进程切换，必然会使整个系统的效率降低
4. 调度的目标(调度算法的评价指标)(学公式)
    1. 不存在一种调度算法，能够同时满足所有的调度目标
    2. 系统吞吐量：单位时间内系统完成的作业数量。长作业会降低吞吐量，短作业有助于提升吞吐量
    3. 周转时间：作业从提交到完成所经历的总时间。包括：作业在外层等待高级调度的时间、进程在就绪队列排队的时间、进程的CPU使用时间、进程等待IO完成的时间
    4. 带权周转时间($>=1$)：计算周转时间是CPU运行时间的多少倍(**注意：分母是作业的CPU运行时间，不包含IO阻塞时间**)。和周转时间一样，越小越好
    5. 等待时间：**周转时间−CPU运行时间-IO阻塞时间**
        ![[Pasted image 20260618220240.png]]
    6. 加平均用来评价整体性能
    ![[Pasted image 20260618214938.png]]
5. CPU调度算法
    1. 先来先服务(FCFS)
        1. 每次从队列中选择等待时间最长的进行调度(越早到的，CPU不空时等的越久)
        2. 非抢占式：只有进程终止或者阻塞，才会交出CPU
        3. FCFS对长作业有利(相比SJF，SJF会让长作业饥饿)(相比之下的有利)
        4. FCFS对短作业不利：你买一杯奶茶，排你前面的人买一千杯，你等待的时间远远超出你所需的服务时间(带权周转时间大)(固有的、客观的不利)
        5. FCFS效率较低，常被结合到其他调度策略中进行使用
        6. FCFS更利好CPU繁忙型作业(相比于IO繁忙型作业)
            1. **FCFS不分辨类型**
            2. 如果IO繁忙型排到一个长CPU繁忙型后面，那它就得一直等CPU，而IO设备空闲，自己的周转时间也变长
            3. 反之，如果让IO繁忙型排前面，由于IO繁忙型CPU用的不长，用一下就会开启IO，这时候对CPU繁忙型影响不大，还能够利用IO与CPU并行
            ![[Pasted image 20260619102024.png]]
            ![[Pasted image 20260619102119.png]]
        ![[Pasted image 20260619091602.png]]
        ![[Pasted image 20260619093634.png]]
    2. 短作业优先(SJF)/短进程优先(SPF)
        1. 选择**预计CPU运行时间最短**的作业/进程(不考虑IO阻塞时间)
        2. 分为抢占式和非抢占式，未说明时**题目默认非抢占式**
        3. SRTN算法的抢占时机：新进程到达导致就绪队列改变、原进程完成或终止
        4. 利好I/O密集型：因为I/O密集型作业通常单次CPU占用时间短，这是SJF选进程的依据
        5. 三个平均指标相较于FCFS均更优，其中**抢占式的(SRTN)可以达到三个指标在所有调度算法里均最优**
        6. 考试如果直接说SJF能达到三项最优是错误的，但有时判对，有时判不对。见到这个选项的话，要比对后选择更优的答案
            1. 所有进程同时可运行/几乎同时到达时：SJF的效果和SRTN是一样的，所以也可以得到最优
            ![[Pasted image 20260619105031.png]]
        7. 缺点补充：SJF未考虑作业的紧迫程度，因此无法保证紧迫性作业被及时处理
        ![[Pasted image 20260619101153.png]]
        ![[Pasted image 20260619143000.png]]
    3. 高响应比优先(HRRN)
        1. 计算响应比时：分子分母的**要求服务时间仅指CPU运行时间**(依然不含IO阻塞)
        2. HRRN是FCFS和SJF的权衡折中版本
        3. FCFS、SJF、HRRN主要关心公平性和系统性能指标，不关心响应时间和任务紧急性。故这三种算法均不适用于分时系统和实时系统，而适用于批处理系统
        ![[Pasted image 20260619105700.png]]
    4. 时间片轮转(RR)
        1. 调度时机：进程在时间片内执行完毕、时间片耗尽
        2. 在t时刻，若进程A刚好用完时间片，而进程B新到达，那么就绪队列中B应该排在A前面
        3. 时间片的大小对系统性能有显著影响，设计时间片时应在响应速度与运行效率之间取得平衡
            1. **时间片太大**，比每个进程运行时间都大时，会退化成FCFS算法，**增大进程响应时间**
            2. **时间片太小**，会导致系统频繁进行进程调度和上下文切换，**造成巨大的系统开销**
            3. 一般来说，设计时间片时要让切换进程的开销占比不超过$1\%$
        4. 适合分时系统    
        ![[Pasted image 20260619130432.png]]
    5. 优先级调度算法
        1. 为每个作业或进程分配一个优先级，以反映其紧迫程度
        2. 抢占时机：就绪队列变化时，就检查是否需要抢占
        3. 可以按照不同优先级组织多个就绪队列
        4. 优先级：静态与动态、设置原则
            1. 静态优先级：优先级在进程创建时确立，并在其整个运行期间保持不变。优点是实现简单，开销小；缺点是不够灵活，低优先级进程可能饥饿
            2. 动态优先级：进程创建时得到一个初始优先级，该优先级随着进程推进或等待时间增加而动态调整。调整方式举例：若进程频繁IO，则提升优先级；规定优先级随等待时间增加而提高；若进程占用CPU时间长，则降低优先级
            ![[Pasted image 20260619134449.png]]
        5. 适合实时系统    
        ![[Pasted image 20260619132502.png]]
    6. 多级队列调度算法
        1. 先选定队列，再利用调度算法从队列中选进程
        2. 选择队列时，可以采用固定优先级或时间片划分
            1. 固定优先级：高优先级队列空时，才能选择低优先级队列并执行调度
            2. 时间片划分：按比例给每个队列分配时间片，时间片内只执行该队列内进程的调度
        3. 每个队列的进程具有相似性，可对每个队列独立采用符合其特性的调度算法
        ![[Pasted image 20260619134900.png]]
    7. 多级反馈队列调度算法(集大成者)
        1. 动态调整进程所处的队列(优先级)和对应的时间片大小
        2. 第1级队列优先级最高，时间片最小，队列内部RR。最后一级队列通常时间片很大，近似FCFS
        3. 仅当高优先级队列为空时，才调度次优先级队列中的进程
        4. 适合分时系统：能保证进程在一定时间内获得了时间片
        ![[Pasted image 20260619141041.png]]
    8. 基于公平原则的调度算法(以公平性为核心)(看看即可)
        1. 保证调度算法：尽量保证每个进程平分CPU时间
            1. 对进程公平，但未必对用户公平(每个用户拥有的进程数不同)
            ![[Pasted image 20260619150620.png]]
        2. 公平分享调度算法：保证每个用户获得相同的CPU时间，或按固定比例分配
            ![[Pasted image 20260619151100.png]]
    9. 多处理机调度(SMP调度)
        1. 多处理机系统分类：非对称多处理机(AMP）、对称多处理机(SMP)
            ![[Pasted image 20260619151813.png]]
        2. 多处理机调度的任务：决定哪个进程上CPU，上哪个CPU
        3. 多处理调度追求的目标：负载均衡、处理机亲和性
            ![[Pasted image 20260619152147.png]]
        4. 调度方案
            1. 公共就绪队列：系统中仅设置一个公共就绪队列，所有CPU共享该队列
                1. 注意CPU访问公共就绪队列时要加锁，实现互斥
                2. 软亲和只是"尽量"，并不是强制。进程依然可以在多个CPU上运行
                3. 软硬亲和可混用
                ![[Pasted image 20260619152510.png]]
            2. 私有就绪队列：系统为每个CPU设置一个私有就绪队列，CPU空闲时，从对应的私有就绪队列中选一个进程运行
                1. 该方案很好地实现了处理器亲和性，缺点是必须进行负载均衡
                2. 平衡负载的方案：推迁移、拉迁移(常结合使用)
                    1. 推拉迁移会稍微降低亲和性
                    ![[Pasted image 20260619153043.png]]
                    ![[Pasted image 20260619153126.png]]
