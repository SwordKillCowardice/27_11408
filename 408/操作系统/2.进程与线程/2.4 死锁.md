# 1.知识点
1. 死锁的概念
    1. 定义：多个进程因竞争资源而陷入相互等待的僵局，每个进程都在等待其他进程所占有的资源，而这些资源又不会被释放，从而形成一个循环等待链。此时，所有相关进程都被永久阻塞，若无外部干预，它们将永远无法推进
    2. 死锁 VS 饥饿 VS 死循环
        ![[Pasted image 20260625145338.png]]
    3. 死锁产生的原因
        1. **这里的2和3隐式点出了存在循环等待现象**
        2. 竞争系统资源(独占资源分配不当)：多个进程**竞争有限的不可剥夺资源**(如打印机)，且**资源分配策略不当**时，就可能死锁。对可剥夺资源(如CPU)的竞争是不会导致死锁的
        3. 进程推进顺序非法：**各进程请求和释放资源的顺序不合理**，导致死锁
            ![[Pasted image 20260625150214.png]]
        4. 同步机制使用不当：如生产者消费者问题中，先P(mutex)再P(empty)。这里的信号量可以视为一种**逻辑资源**
    4. 死锁产生的必要条件：其中任一条件不成立，则不可能死锁
        ![[Pasted image 20260625150908.png]]
        1. 发生死锁时一定有循环等待，但发生循环等待时未必死锁(资源分配图中存在环，并不必然意味着死锁)
        2. 原因：死锁环中的某个资源数量大于1，环外的进程释放该资源时，就可以消除这个环中的一条边，从而破坏死锁条件
        3. 只有当系统中**每类资源均只有一个实例时**，循环等待(资源分配图中有环)才是死锁的充要条件。否则，有环仅代表系统处于潜在风险状态
        ![[Pasted image 20260625151145.png]]
    5. 死锁的处理策略(四种)
        1. 预防死锁：破坏死锁的四个必要条件中的一个或多个，杜绝死锁发生
        2. 避免死锁：用算法防止系统进入不安全状态，从而避免死锁发生
        3. 检测及解除死锁：允许死锁发生，操作系统负责检测并消除死锁
        4. 鸵鸟策略：忽略死锁，假定死锁不会出现。被大多数通用OS使用
        ![[Pasted image 20260625153008.png]]
        ![[Pasted image 20260625153238.png]]
2. 死锁预防：破环死锁产生的四个必要条件之一
    1. 破坏互斥条件：将原本只能互斥使用的资源改造为允许多个进程共享访问(如SPOOLing技术)。但许多资源本质上不支持并发访问，否则会导致数据不一致等问题。为了保障系统正确性，**破坏该条件在实践中并不可行，做题时认为无法破坏！**
        ![[Pasted image 20260625154806.png]]
    2. 破坏不可剥夺条件：**在实际系统中极少采用**
        1. 实现复杂
        2. 强制释放已获得的资源可能造成已完成的工作失效，甚至导致设备状态混乱
        3. 频繁地申请与释放资源会增加系统开销，降低系统吞吐量
        4. 频繁放弃资源并重新申请，可能导致进程饥饿
        ![[Pasted image 20260625155129.png]]
    3. 破坏请求并保持条件：要求进程在请求新资源时不得持有任何不可剥夺资源
        ![[Pasted image 20260625160054.png]]
        ![[Pasted image 20260625160431.png]]
        1. 源源不断地有A类进程占有资源1，B类进程占有资源2，导致C类进程迟迟无法成功申请到两类资源，导致饥饿
        ![[Pasted image 20260625160450.png]]
    4. 破环循环等待条件：采用资源有序分配法。为系统中每类资源赋予一个编号，规定进程**必须按照编号递增**的顺序请求不同类资源，且同类资源需一次性申请。已持有大编号资源的进程无法再请求小编号资源，从而避免了资源分配图中环的出现
        ![[Pasted image 20260625161700.png]]
        ![[Pasted image 20260625161723.png]]
        ![[Pasted image 20260625161741.png]]
        ![[Pasted image 20260625162040.png]]
3. 死锁避免：判别分配安全性，避免系统进入不安全状态
    1. 系统安全状态
        1. 系统中有至少一个安全序列时，称系统处于安全状态，否则称系统处于不安全状态
        2. 安全序列：如果系统按照这种序列分配资源，则每个进程都能顺利完成
        3. 系统处于安全状态时，一定不会发生死锁；发生死锁时，系统一定处于不安全状态，但不安全状态不一定会演变为死锁
    2. 银行家算法(死锁避免算法)
        1. 思想：在进程提出资源申请时，先评估此次分配的安全性：若分配后系统仍处于安全状态，则允许分配；否则进程等待
        2. 相关数据结构
            1. 每个进程在**运行前需声明**对各类资源的**最大需求量**(这个需求量在进程整个生命周期内不改变)，对应Max中一行。该需求量不得超过系统资源总量

        3. 安全性算法(银行家算法的最后一步)：用于判断系统当前是否处于安全状态，基本思想是尝试找出一个安全序列

4. 死锁检测与解除：允许死锁发生，操作系统负责检测并消除死锁
    1. 死锁检测
        1. 采用资源分配图来检测系统是否处于死锁状态。圆圈节点代表进程，矩形框节点代表一类资源，框中的圆点数代表该类资源的个数。进程指向资源的边称为请求边，表示该进程申请一个单位的该类资源(**正在申请、但尚未得到**)；资源指向进程的边称为分配边，表示该类资源有一个分给该进程(**已经被分配**)

        2. 算法流程+死锁定理：不断找出可以继续运行的进程节点，删去与其相连的边。如果最终能删除图中所有边，则系统处于非死锁状态；反之处于死锁状态。**化简过后仍有边相连的进程即为死锁进程**

1. 死锁的判别
    1. 题目一：可能导致死锁的事件
        1. 总结：**选项可能导致死锁⟺选项中明示或暗示了"循环等待"的可能性**
        2. 进程进入死循环，只是自己的逻辑问题，**并不涉及其他进程**，不满足**死锁至少需要两个及以上进程**互相等待的条件，故不可能导致死锁
        3. 共享设备本身就允许多个进程一起使用，破坏了死锁的互斥必要条件，故不可能导致死锁
        4. D项**即使改成**竞争使用**互斥型**设备**也不正确**：因为竞争资源是并发程序设计必然面对的，你仅仅指出在竞争并不足够论证死锁有可能性。额外**加上系统资源分配不当条件**，隐式点出**形成循环等待**，才可能导致死锁(见死锁成因)
