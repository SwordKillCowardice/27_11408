# 1.知识点
1. 同步与互斥：进程之间最基本的两种制约关系
    1. 临界资源
        1. 定义：在同一时刻仅允许一个进程访问的资源，如打印机、被多个进程共享的变量和数据结构等
        2. 对临界资源的访问过程(四部分)
            1. 在进入区上锁，在退出区解锁。进入区和退出区**负责实现互斥**
            2. **每个进程都拥有自己完整独立的四个部分**(进入区、临界区、退出区、剩余区)，这四部分物理上都是该进程自己的指令序列，彼此互不重叠
            ![[Pasted image 20260620153635.png]]
    2. 同步(直接制约关系)：为完成某种任务而建立的两个或多个进程，由于需要**协调彼此的运行次序**(解决异步问题)，而在执行过程中产生等待或传递信息的制约关系。同步关系源于进程之间的合作。管道通信是个不错的例子：写进程先写，读进程才能读；缓冲区满了之后，读进程先读，写进程才能继续写
    3. 互斥(间接制约关系)：当一个进程正在使用临界资源(执行**自己的**临界区代码)时，其他试图访问**该资源**的进程必须在**自己的进入区**中等待；只有当占用临界资源的进程退出临界区(执行完**自己的**临界区代码)后，**即释放该资源**，其他进程才被允许开始执行**自己的**临界区代码
    4. 临界区同步与互斥的设计原则
        1. 让权等待：原则上必须遵循，但非必须(如peterson算法就没实现)
        2. 除了让权等待外，其他三个必须遵循
        3. 忙等待：进程在等待某个条件满足(比如等锁被释放)的过程中，**不释放CPU，而是持续占用CPU去反复检测这个条件**，直到条件满足为止
        ![[Pasted image 20260620161510.png]]
2. **实现临界区互斥的基本方法**
    1. 软件实现方法
        1. 以下软件实现方法均不满足让权等待
        2. **在进入区设置并检查一些标志，用来表明是否有进程正在临界区中**。若有，则其他进程在进入区通过循环检查的方式等待；当进程离开临界区后，在退出区修改相应的标志，以允许其他进程进入
        3. 单标志法：设置公用整型变量turn，指示当前允许进入临界区的进程编号。当进程退出临界区时，把临界区的使用权交给另一个进程(**谦让**)：即把turn置为另一个进程的编号
            1. 每个进程进入临界区的**权限只能被另一个进程赋予**
            2. **满足忙则等待**(同一时刻最多只允许一个进程访问临界区)
            3. **违背空闲让进**：两个进程必须轮流进入临界区，若某个进程不进入，则另一个进程也无法进入(无法获得权限)
            4. **违背有限等待**(这个有争论，看后面做题情况)和**让权等待**
            ![[Pasted image 20260620165420.png]]
            ![[Pasted image 20260620170416.png]]
            ![[Pasted image 20260621091351.png]]
        4. 双标志先检查法：设置布尔型数组flag\[2]，flag\[i]=true表示进程Pi想要进入临界区(**进入意愿**)。Pi进入临界区前，先检查对方是否想进入。若对方想，则等待；否则，把自己的flag\[i]置为true，然后进入临界区。退出临界区把flag\[i]置false
            1. 进程无需交替进入临界区，可以连续使用临界区
            2. **违反忙则等待**：P0执行完1后，切换至P1执行5。此时PO还未设置标志，所以P0和P1双双进入临界区\[**检查(对方标志)和上锁(设置自己标志)不是一气呵成的**]
            ![[Pasted image 20260621090216.png]]
            ![[Pasted image 20260621091243.png]]
        5. 双标志后检查法：**先上锁(设置自己标志)，后检查(对方标志)**
            1. **仅满足忙则等待**
            2. **违背空闲让进和有限等待**：P0执行1，然后P1执行5，两个都阻塞，永远无法进入临界区
            ![[Pasted image 20260621091747.png]]
            ![[Pasted image 20260621092232.png]]
        6. Peterson算法：利用flag数组解决互斥访问问题，利用turn变量解决"饥饿"。flag\[i]=true依然表示意愿，而turn=i表示两个进程同时请求时，优先允许Pi进入临界区
            1. 在进入区，进程表达自己想进去(设置flag)，同时谦让对方(设置turn)
            2. 如果对方想进去(flag\[1])，而且最后一次做出谦让的是自己(turn\==1)，则等待，否则进入
            3. 红包的例子：turn就相当于过年阿姨给你塞红包，互相说的客套话。如果阿姨最后说客套话，那红包就归你；反之归阿姨。如果进程P0进行最后一次谦让，那么进入权就归P1；反之归P0
            4. **除了让权等待，都满足**

    2. 硬件实现方法
        1. 中断屏蔽不适用于忙等概念，另外两种都有忙等
        2. 使用特殊的硬件指令(具有原子性)实现临界区的互斥访问
        3. 中断屏蔽方法(关中断)：进临界区前关中断，执行完临界区代码再开中断。由于中断屏蔽，该过程中无法进行进程切换，从而该进程可以不受干扰地完成对临界区的访问(本质就是让该进程在执行期间独占CPU，从根本上避免冲突)
            ![[Pasted image 20260621095855.png]]
            1. 优点：简单高效
            2. 缺点：
                1. 不适用于多处理器系统：关中断只能卡死一个CPU，其他CPU上的进程依然可以访问同一临界区
                2. 只适用于操作系统内核进程，不适合用户进程：开关中断指令对系统影响很大，不能随意交给用户进程使用
                3. 限制了CPU的并发执行能力，显著降低系统效率：该进程独占CPU期间，无法切换其他不使用该临界区的进程(尤其是IO密集型进程)进行调度，这就无法充分利用系统资源
        4. TestAndSet指令(TS/TSL)(硬件实现的指令)：借助TS指令实现互斥，**该指令是原子操作**。其功能为：读取指定标志的当前值，并立即置其为true，然后返回读到的旧值
            1. 使用TS指令管理临界区时，需要为每个临界资源设置一个共享布尔变量lock(锁，初值false，表示资源空闲)
            2. 看起来唬人，本质就是**检查和上锁步骤作为原子操作**，代码逻辑简明
            3. while条件里**重复用TS指令**：管你3721，先把lock旧值读出来，再立刻上锁。如果旧值是真，那就等别人用完(此时上锁操作无用)；别人用完后，把lock释放了(旧值变成假)，上完锁美美开始运行
            4. 优点：相比软件方法更简单、适合多处理器环境(lock是共享变量)、支持任意数量进程
            5. 缺点：忙等(不满足让权等待)、锁的获取顺序不确定，可能导致饥饿
            6. 下面这些都只是为了方便理解的伪代码，实际实现并非如此，Swap同理
            ![[Pasted image 20260621101557.png]]
        5. Swap指令(硬件实现的指令)(Exchange指令/XCHG指令)：**也是原子操作**
            1. 使用Swap指令管理临界区时，需要为每个临界资源设置一个共享布尔变量lock(锁，初值false，表示资源空闲)；**并在每个进程中定义一个局部变量old**，每次尝试进入临界区前将其初始化为true(**就是上锁**)
            2. 除了第一轮while之外，其他每轮逻辑和TS指令一模一样
            3. 优缺点同上
            ![[Pasted image 20260621103041.png]]

    2. available=true：锁是空闲的(资源可用)
    3. 保证操作的原子性：否则又会违反忙则等待原则(多个进程同时进入)

4. **信号量**：一种强大的同步机制
    1. 定义
        1. 信号量机制是一种强大的同步机制，既能解决互斥问题，又能解决同步问题
        2. 信号量S其实就是一个变量，可以用于**表示系统中某种资源的数量**
        3. 通过一对低级进程通信原语访问信号量：wait(S)\[P(S)]和signal(S)\[V(S)]
        4. P(S)代表申请资源，V(S)代表释放资源。**考试时若未特殊说明，默认S为记录型信号量**
    2. 整型信号量：用一个整型变量S表示某类资源的可用数量。与一般整型变量不同，其仅支持初始化、wait操作和signal操作
        1. 缺点：忙等，而且和互斥锁一样，一直独占CPU
        ![[Pasted image 20260621123318.png]]
    3. 记录型信号量：用记录型数据结构表示的信号量，**通过阻塞机制实现了让权等待**
        1. 等待队列L：用于链接所有因请求该资源而被阻塞的进程
        2. S.value的初值为可用资源的数目。S.value<0时：其绝对值等于被阻塞进程数
        3. **不会忙等**：没资源时自己阻塞
        ![[Pasted image 20260621123808.png]]
    4. 利用信号量实现进程互斥(四步走)
        1. 划定临界区(**分析互斥关系**：...不能同时访问)
        2. 为临界资源设置一个互斥信号量mutex，初值为1
        3. 进入区进行P操作
        4. 退出区进行V操作
        5. **注意事项**
            1. 临界区**紧紧夹在**PV操作之间，中间不能插入其他无关代码
            2. 定义信号量的写法：用semaphore mutex=1就行。如果题目要求写出结构体，再写结构体
            3. 不同临界资源用不同互斥信号量
            4. PV操作成对出现
            5. 若系统中存在多个同类资源，应将信号量初值设为资源总量
        ![[Pasted image 20260621132504.png]]
    5. 利用信号量实现进程同步(四步走)(前V后P)
        1. **分析同步关系**：哪些操作必须以前一后
        2. 设置同步信号量S，初始为0
        3. 前操作之后用V(S)
        4. 后操作之前用P(S)
        ![[Pasted image 20260621133436.png]]
    6. 利用信号量实现前驱关系：每对前驱关系都对应一个同步关系，故每条前驱边设置一个同步信号量，初值为0，PV使用同进程同步

6. 管程：比信号量更高层的同步互斥机制(抽象层次更高，封装了内部细节)
    1. 引入原因：为了更方便地实现进程同步和互斥
    2. 定义：管程是由**共享数据结构**及其**操作过程**共同组成的**资源管理程序**
        1. 共享数据结构对应系统中的共享资源
        2. 像类：共享数据结构对应成员变量，过程对应成员函数，初始化对应构造函数
        ![[Pasted image 20260622140431.png]]
    3. 基本特征：互斥性+封装性
        1. 管程内部的共享数据结构只能被管程自身的过程访问(封装性)
        2. 外部进程必须调用管程内的过程才能访问资源(封装性)
        3. 任意时刻仅允许一个进程执行管程内的过程，从而实现互斥访问(互斥性)(由编译器实现)
    4. 条件变量(管程实现同步的途径)：将不同的阻塞原因抽象为独立的条件变量，每个条件变量维护一个等待队列，队列中是因该条件阻塞而让出管程的进程。条件变量仅支持PV操作
        ![[Pasted image 20260622143217.png]]
        ![[Pasted image 20260622143254.png]]
    5. 管程使用示例(生产者-消费者问题)(浏览即可)
        1. 用monitor和end monitor声明管程
        2. 用condition声明条件变量，用于同步
