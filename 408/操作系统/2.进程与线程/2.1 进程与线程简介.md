# 1.知识点
1. 进程的概念
    1. 进程的作用(为何引入)
        1. 为有效描述和控制程序的并发行为，操作系统引入了进程的概念，以支撑操作系统的并发性与共享性(程序静态，刻画并发不准确，所以引入动态的进程)
        2. 操作系统通过进程控制块(PCB)记录进程的基本信息和运行状态，从而实现对进程的控制与管理
        3. 创建进程的本质是创建其PCB，撤销进程则释放其PCB
    2. 进程实体(进程映像)：由PCB、程序段、相关数据段组成
        1. 进程实体是静态的，反映了进程在某一时刻的状态(快照)
        2. 完善程序运行的过程：程序运行前，会创建相应的PCB
        ![[Pasted image 20260616120345.png]]
    3. 进程的定义：进程是进程实体的运行过程，是系统**进行资源分配和调度**的一个独立单位
        ![[Pasted image 20260616104127.png]]
    4. 进程的特征(理解)
        1. 动态性是进程最根本的特征
        ![[Pasted image 20260616104220.png]]
    5. 程序 VS 进程：根本区别就是静态和动态
        ![[Pasted image 20260626112021.png]]
2. 进程的组成(三部分)
    1. 进程控制块(PCB)(核心)
        1. PCB包含的内容：进程标识信息、进程调度信息、资源和内存信息、处理机状态信息
            ![[Pasted image 20260616110339.png]]
        2. PCB的作用
            1. 进程创建时，OS为其分配一个PCB。PCB常驻内存，在进程终止时回收
            2. PCB是进程存在的唯一标志，是系统感知和管理进程的途径。在进程的整个生命周期内，系统始终依赖PCB对其进行管理
    2. 程序段：进程中可被CPU执行的代码部分，可被多个进程共享(比如在电脑上打开三个QQ)
    3. 数据段：进程运行所需的各种数据。每个进程的**数据段是私有的**，保证独立和安全
    4. PCB是给操作系统使用的，程序段和数据段是给进程自己使用的
3. 进程的内存映像
    1. 定义
        1. 当程序被加载运行时，OS会为其建立一个虚拟地址空间，该空间的逻辑布局称为进程的内存映像
        2. 内存映像反映了进程在运行时代码、数据、堆栈等的组织方式，是动态的
        3. 进程的整个地址空间无需全部驻留内存，按需调入即可
    2. 组成部分
        1. 代码段：存放编译后的可执行代码，通常只读。常量也放这里
            ![[Pasted image 20260616131617.png]]
        2. 数据段：存放全局变量和静态变量(static)
            ![[Pasted image 20260616131702.png]]
        3. 堆：程序运行时动态申请内存的区域(malloc、free)。从低地址向高地址增长，大小不固定
        4. 栈：支持函数调用，存放局部变量、函数参数、返回地址等临时信息，由系统自动管理。从高地址向低地址扩展
        5. 共享库的存储映射区：共享库用于提供进程所依赖的公共函数代码(如printf库函数)，在运行时被动态映射到进程的地址空间。代码是只读的，可被多个进程共享
        6. 图示

5. 进程的状态与转换
    1. 通常，进程具有以下五种状态，其中**前三种为基本状态**(进程生命周期中的大部分时间都处于基本状态)
    2. 进程PCB中，会有一个变量来标识进程的当前状态
    3. 运行态：进程正在CPU上执行
    4. 就绪态：进程已获得除CPU外的所有必要资源。一旦获得CPU，即可运行
    5. 阻塞态(等待态)：进程因等待某一事件(除CPU外的资源、其他进程响应等)而暂停运行
    6. 创建态(新建态)：进程正在被创建。在这个阶段，OS会为该进程初始化PCB、分配资源。所有必要资源到位后，进程进入就绪态。创建态是一个短暂的中间状态
    7. 终止态(结束态)：进程已完成执行(无论正常结束，还是被强行终止)，正在等待系统回收其资源。此时，进程不再参与调度，但PCB等信息可能暂时保留，直至完成最终清理
    8. **状态转换图及其原因**
        1. 运行态 to 就绪态(补充)：在可剥夺式调度系统中，若有更高优先级的进程变为就绪态，则当前运行的进程也会被强制切换为就绪态，让出CPU
        2. 进程从运行态变为阻塞态是一种主动行为(由自身发起的系统调用触发。但并非所有系统调用都会导致阻塞，只有需要等待外部事件才会)，因此就绪态的进程无法直接变为阻塞态(没上CPU，无法主动发起系统调用)
        3. 进程从阻塞态变为就绪态是一种被动行为，依赖于外部事件的发生或其他进程的协助
        4. 状态图之外的状态转换是不存在的：不能直接从阻塞态到运行态，也不能直接从就绪态到阻塞态
        ![[Pasted image 20260616153846.png]]
6. 进程控制
    1. 进程控制的功能是对系统中所有进程进行有效的管理，主要包括创建新进程、撤销已有进程、实现进程状态转换等(简化理解为：实现进程状态转换)
    2. 用**原语**实现进程控制(原语的执行具有原子性，执行期间不会被中断)

7. 进程的通信(IPC)
    1. 引入
        1. 进程通信是指进程之间的信息交换
        2. 根据通信效率和数据量的不同，可分为低级通信和高级通信
            1. 低级通信主要用于传递控制信息(如同步、互斥)，PV操作就是低级通信
            2. 高级通信用于高效传递大量数据
        3. 进程通信需要OS协助：各进程拥有相互独立的内存地址空间，且不能直接访问对方的内存地址空间(为了安全)，所以需要OS协助传递信息
    2. 共享存储
        1. 定义：进程通过特殊的系统调用，创建一段独立的内存区域，并将其映射到多个进程的虚拟地址空间中(通过增加页表项/段表项来实现)。该区域就是共享区域，参与通信的进程通过对这一区域进行读写来交换信息
            ![[Pasted image 20260616202958.png]]
        2. 类型：基于数据结构、基于存储区
            1. 基于数据结构的共享：限制了数据形式，不够灵活，降低了速度
            2. 基于存储区的共享：在保持不出错的情况下，进程想怎么写就怎么写，想怎么读就怎么读，灵活性高，速度快
            ![[Pasted image 20260616203626.png]]
        3. 操作系统仅负责分配共享区域并完成地址映射，**并不会自动提供同步保护**
        4. **用户程序**需引入同步互斥机制，**自行实现读写逻辑和同步控制**，避免访问出错
    3. 消息传递
        1. 定义：进程间的数据交换以格式化的消息为单位，通过OS提供的发送原语和接收原语进行
            ![[Pasted image 20260616205856.png]]
        2. 类型：直接通信方式、间接通信方式
            1. 直接通信：发送进程通过发送原语将消息**发给指定的接收进程**(要指明接收进程的ID)，内核负责将消息从发送方复制到接收方的内核缓冲队列中，接收方通过接收原语接受消息
                1. 发送方在自己的地址空间初始化消息，然后使用发送原语
                ![[Pasted image 20260616210158.png]]
                2. 内核将消息从发送方(的地址空间)复制到接收方的内核缓冲队列(消息队列)中
                ![[Pasted image 20260616210427.png]]
                3. 接收方使用接收原语接收消息，复制到自己的地址空间中
                ![[Pasted image 20260616210645.png]]
            2. 间接通信(信箱通信方式)：发送进程将消息投递到信箱(要指明发送到哪个信箱)，接收进程从信箱中取出消息
                1. 发送方在自己的地址空间初始化消息，然后使用发送原语
                ![[Pasted image 20260616211104.png]]
                2. 内核将消息从发送方(的地址空间)复制到信箱A中
                ![[Pasted image 20260616211143.png]]
                3. 接收方使用接收原语从信箱A接收消息
                ![[Pasted image 20260616211234.png]]
            3. 无论哪种方式，消息的投递均由OS内核完成
        3. 优点
            1. 将通信的底层细节封装在内核中，对用户透明，简化了应用程序设计
            2. 消息传递是目前应用最广泛的进程间通信机制，应用于微内核OS中微内核与服务器之间的交互、多处理器系统、分布式系统、计算机网络
    4. 管道通信
        1. 定义：管道通信是一种基于先进先出原则的进程间通信机制，常用于具有亲缘关系的进程之间，以生产者-消费者模式进行数据交换
        2. 实现细节
            1. 管道表现为一种特殊的共享文件，但实际上是由OS内核维护的一块固定大小的内存缓冲区(实现上是循环队列)
            2. 某一时间段数据流动只能是单向的
            3. 互斥(OS)：任一时刻只允许一个进程对管道进行读或写，防止数据混乱
            4. 同步：管道满时，写进程自动阻塞；管道空时，读进程自动阻塞
            5. 写端关闭检测：写端关闭时，读端read()返回0，表明无数据可读
            6. 管道非空就可以读，管道非满就可以写
            7. 一个管道允许多个写进程，一个读进程(**考试标准**)

8. 线程
    1. 定义
        1. 引入线程的原因：应对程序内部的并发需求(QQ同时发文件和打视频)。进一步降低程序并发执行时的时空开销，提升操作系统的并发性能
            ![[Pasted image 20260617101121.png]]
            ![[Pasted image 20260617095843.png]]
        2. 定义：线程是进程内部的一条执行流，是**程序执行流的最小单元**，也是**处理器调度的基本单位**
    2. 线程的属性
        1. 线程是轻量级执行实体：线程本身**不拥有独立的系统资源**，但拥有运行所必须的私有数据结构(线程ID、程序计数器、寄存器集合、栈)。**每个线程都有唯一的ID和TCB(线程控制块)**，来记录执行上下文
        2. 资源共享：同一进程内的所有线程共享该进程的代码段、数据段、堆、文件描述符等系统资源。因此，线程间通信直接读写共享内存，无需IPC，非常高效；多个线程可并发执行同一份代码，服务不同请求
        3. 线程是处理机调度和执行的基本单位。在多CPU系统中，多个CPU可以同时执行同一进程的不同线程，显著缩短该进程的执行时间
        4. 线程也有就绪、运行、阻塞三种基本状态
        5. 同一进程中的线程切换，不会引起进程切换；不同进程中的线程切换，才会引起进程切换；切换同进程内的线程，开销很小；切换进程，开销很大
        6. 一个进程中的线程对其他进程完全不可见
        7. 线程的创建和撤销所需的系统开销远低于进程
    3. 引入线程后带来的变化
        1. **进程**成为**除CPU外的系统资源分配**单位(如分配打印机、内存地址空间)，而**线程**成为**CPU调度和执行**的基本单位
        2. 提升并发度：进程之间可以并发，线程之间也可以并发

    6. 线程的实现方式
        1. 用户级线程(ULT)：只有用户视角能看到线程
            1. 应用程序使用**线程库**创建线程，**在用户态范围内**客观存在(有真实的数据结构和执行上下文)，但**对OS不可见，OS仍然以进程为调度单位**
            2. 所有**线程管理工作**(创建、切换、撤销)均由**应用程序在用户态完成**，线程切换无需CPU变态
            3. 优缺点
                1. 用户态线程库确实能管理线程，**但前提是CPU的执行权还在用户态**。一旦某个线程调用了阻塞型系统调用，CPU瞬间转入内核态，**这个转移过程不会经过线程库**，线程库连"反应"的机会都没有，更别说提前切换线程避免全挂(线程库无法在一个线程阻塞时切换到另一个线程)
                ![[Pasted image 20260617112932.png]]
                ![[Pasted image 20260617113000.png]]
            ![[Pasted image 20260617112405.png]]
        2. 内核级线程(KLT)(内核支持的线程)：从OS内核视角能看到线程
            1. 应用程序依然使用**线程库**创建线程，线程客观存在。**线程对OS可见，OS为每一个内核级进程维护一个TCB，并把线程作为CPU调度的基本单位**
            2. 线程的业务代码仍在用户态跑，只有调度决策和切换在内核态，线程切换需要CPU变态
            3. 大多数现代OS都实现了内核级线程，如Windows、Linux
