2. 操作系统内核
    1. 定义：操作系统内核是**常驻内存的核心组件**，由以下部分(内核程序)构成：与硬件紧密相关的模块（中断处理、设备驱动）、运行频率较高的模块（时钟管理、进程调度）、各模块共用的基础操作。内核是最接近硬件的部分
    2. 设计目的：**保护核心模块**免受应用程序破坏、**提升**操作系统的**运行效率**
    3. 两大功能：支撑功能(**和硬件结合最为紧密**)、系统资源管理功能
        1. 支撑功能：为操作系统其他模块提供基础支持
            1. 时钟管理：向用户提供标准系统时间、利用时钟中断实现任务调度
            2. 中断机制：允许CPU在I/O期间执行其他指令，从而提高资源利用率。当发生中断时，内核负责保存当前进程的现场，把控制权交给相应的处理程序，并在处理完成后恢复现场
            3. 原语：由若干条指令组成、用于完成特定功能的操作。具有**原子性**，执行过程不可被中断，必须一气呵成(通过**关闭中断**确保执行不被干扰)。运行在内核态，执行时间短、调用频繁
        2. 系统资源管理功能：操作系统通过一系列核心数据结构(如进程控制块)对系统资源进行统一管理，提供三类基本管理功能
            1. 进程管理
            2. 存储器管理
            3. 设备管理
3. 操作系统按结构划分
    1. 划分总览图
        ![[Pasted image 20260615094846.png]]
    2. 分层结构：将操作系统划分为若干层次，各层仅可调用紧邻下层提供的功能和服务(单向依赖)
        ![[Pasted image 20260615095805.png]]
        1. **便于调试和验证**(核心优势、存在理由)：从层1开始逐层开发，完成本层调试之后再开发下一层。这样的话，在下一层遇到问题时，可以直接定位错误位于下一层，因为往下的各层都已经通过调试
        2. 易于扩充和维护：层间接口都已确定。两层之间加一层时，只需让这一层兼容往下的接口，并向上层提供同样的接口
        3. 层次划分困难，且一旦划分好，系统可能缺乏灵活性
        4. 效率低：如果我只想调用一个层1的功能，不能直接调，必须跨越多层
    3. 模块化
        1. 图示
        ![[Pasted image 20260615100758.png]]
        2. 划分模块时，要重视模块的大小和独立性
        ![[Pasted image 20260615101116.png]]
        3. 支持并行开发：各模块之间约定好接口准则，即可各自同时开发
        4. 便于功能扩展：支持动态加载新的内核模块，以扩展功能
        5. 难以调试验证：若A模块和B模块互相调用，当A模块出问题时，难以确定问题问题源头

            3. 微内核优势：广泛应用于对系统可靠性要求极高的领域

            4. 定义微内核结构OS的四个方面
                ![[Pasted image 20260615213807.png]]
        2. 具体对比
            1. 两者均采用了模块化思想
            2. 使用微内核时，用户态下的各个功能模块只能通过"消息传递"来间接通信
            3. 使用宏内核时，任何一个功能模块出错，都可能导致整个系统崩溃，而使用微内核不会
            4. 操作系统内核运行在内核态，操作系统的非内核功能运行在用户态
            5. 宏内核与微内核并非对立，而是相互借鉴、融合发展
            6. 效率分析(**注意这里的微内核取的是理论上的极致微内核，而非考试使用的，考试使用上面微内核设计中的情况**)：使用微内核时，进程管理模块和存储管理模块都位于用户态。用户需要同时请求这两个服务时，只能先分别向两个模块提出请求，两个模块分别再向内核请求各自的服务，从而增大了状态切换的开销
            ![[Pasted image 20260615093321.png]]
    5. 外核：将物理资源直接暴露给用户级系统，自身仅负责资源的安全分配与隔离
        1. 图示：OS=内核+外核，都运行于内核态
            ![[Pasted image 20260615103719.png]]
        2. 外核负责为用户进程分配**未经抽象**的硬件资源，并保证使用安全。进程管理相关工作仍然由内核负责
        3. 优势：核心就在于**未经抽象**，想要连续的空间，那分给你的一定是连续的
            ![[Pasted image 20260615104608.png]]
        4. 缺点：降低了系统的一致性(有的进程找内核分配虚拟存储，有的找外核分配实际存储)、使系统更复杂(理由同前)
4. 操作系统引导(Boot)
    1. 大致的磁盘结构
        1. 活动分区：被BIOS选中用于启动的主分区。这里活动分区恰好是C盘，而且操作系统也安装在C盘中(操作系统安装位置和活动分区可以不同)
        2. 磁盘引导程序：负责继续引导操作系统
        3. 分区表：记录每个分区的大小和地址范围(记录磁盘如何划分)
        ![[Pasted image 20260615115859.png]]
        4. PBR：负责找到启动管理器
        ![[Pasted image 20260615120434.png]]
    2. 定义：开机的时候，怎么让操作系统运行起来
        ![[Pasted image 20260615115214.png]]
    3. 引导过程
        1. 执行BIOS(BIOS包含自举程序)，将MBR读到内存中
        2. 根据MBR找到活动分区
        3. 从活动分区找到PBR
        4. 通过PBR找到启动管理器(也叫引导程序)
        5. 从启动管理器加载操作系统内核
        ![[Pasted image 20260615120757.png]]
        ![[Pasted image 20260615121029.png]]

        2. 虚拟机管理程序(VMM)：一种用于实现硬件虚拟化的软件，  负责创建、管理和运行多个相互隔离的虚拟机
