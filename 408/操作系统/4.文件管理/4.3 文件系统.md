# 1.知识点
1. 文件系统的定义及层次结构(简单了解)
    1. 文件系统是OS的核心子系统之一，**负责对存储设备上的文件和目录进行统一管理**,提供创建、读取、写入、删除和保护等基本操作。**向上**为用户和应用程序提供**抽象接口**；**向下**则与设备驱动协同，**高效调度物理存储资源**

    2. 文件系统层次结构图(参考国外教材)
        1. IO控制：包含设备驱动程序和中断处理程序，负责在内存与磁盘之间传输数据
        2. 基本文件系统：负责向设备驱动程序发送通用命令，以读写磁盘块；管理内存缓冲区，缓存文件系统元数据、目录项及数据块
        3. 文件组织模块：负责建立文件逻辑块与物理块之间的映射关系，将逻辑块地址转化为物理块地址；还包含空闲空间管理器，用于跟踪未分配的磁盘块，并按需分配给文件使用
        4. 逻辑文件系统：负责管理文件系统的元数据，不含实际数据内容。它维护目录结构，并根据给定文件名，向文件组织模块提供所需的元数据；同时通过FCB记录各文件的属性和状态，并负责实现文件保护机制

3. 文件存储空间管理(对空闲磁盘块的管理)
    1. 空闲表法：属于连续分配方式，为每个文件分配一块物理上连续的磁盘区域
        1. 系统为外存中的所有空闲区维护一张空闲表，每个空闲区对应一个表项，包含序号、起始盘块号、空闲盘块数等信息，并按起始盘块号递增排列
        2. 盘块分配同内存动态分区分配，通常采用首次适应、最佳适应等算法
        3. 盘块回收也一样，注意回收时合并相邻空闲区
        ![[Pasted image 20260710100235.png]]
        ![[Pasted image 20260710100607.png]]
    2. 空闲链表法：将所有空闲盘区组织成一条链表，链表节点为单个盘块或一组盘块(考试未说明时，默认指空闲盘块链法)
        1. 空闲盘块链：以单个盘块为单位，每个盘块包含指向下一个空闲盘块的指针
            1. 操作系统保存链头、链尾指针
            2. 适用于离散分配
            3. 分配时：从链首依次取下所需数量的盘块给用户
            4. 回收时：将释放的盘块逐个插入链尾
            ![[Pasted image 20260710102113.png]]
            ![[Pasted image 20260710101432.png]]
        2. 空闲盘区链：以空闲盘区(一组连续的盘块)为单位，每个盘区包含该盘区的盘块数和指向下一个空闲盘区的指针
            1. 操作系统保存链头、链尾指针
            2. 分配同内存动态分区分配
            3. 回收时，需要判断回收区是否与链表中的空闲盘区在物理上相邻，若相邻则合并，合并后空闲盘区增大，可利用性增强，可以有效减少外部碎片
            ![[Pasted image 20260710102144.png]]
            ![[Pasted image 20260710101923.png]]
    3. 位示图法：用二进制的一位表示盘块的使用状况，磁盘上的每个盘块均对应位示图中的一个比特位。该位为0时表示盘块空闲，为1时表示已被分配
        1. 连续分配和离散分配都适用
        2. 如果行号和列号从0开始，则公式需要调整
        3. 行是字号，列是字长
        ![[Pasted image 20260710151728.png]]
        ![[Pasted image 20260710103630.png]]
        ![[Pasted image 20260710104013.png]]
    4. 成组链接法(UNIX系统)：适用于大型文件系统(考题难出)
        1. 将所有空闲盘块分为若干组(如每组100个盘块)，每组中的块号不必连续。除最后一组外，每组的第一个盘块用作索引块，记录**下一组中所有空闲盘块的块号以及数量**
        2. 文件系统挂载时，第一组的空闲盘块信息(块号列表和数量)被加载到内存的**空闲盘块号栈**中，空闲盘块号栈存储在**超级块**中
        3. 倒数第二组的索引块中存放的第一个盘块号为0，用于标志空闲链的结束
        4. 分配空闲块时，若要将某组的索引块分配出去，则把索引块中内容拷贝到空闲盘块号栈中
        5. 回收空闲块时，若栈满，则将栈中内容写入新回收的块，作为一个新组的索引块，然后将新组内容写入栈(将新块设为栈底，栈容量记为1)
        6. 连续分配与离散分配相结合

4. 虚拟文件系统(VFS)
    1. 普通文件系统：由于不同文件系统支持的使用的文件接口不同，用户需要单独为每种文件系统编写一套运行逻辑，开发困难
        ![[Pasted image 20260710122957.png]]
    2. 虚拟文件系统：位于用户程序与具体文件系统之间，向上提供统一的文件操作接口
        1. 有了VFS，用户程序就无需关心底层使用的是哪种文件系统，只需通过标准系统调用就能完成文件操作，VFS负责将请求转发给相应的文件系统进行处理
        2. VFS采用面向对象的设计思想，抽象出一个通用的文件系统模型，并将其中的公共特性**封装为四种对象**。每个对象都包含数据成员和一组操作函数指针，**文件系统需要实现VFS定义的接口，才能被系统使用**
            1. Vnode是对各类文件系统元数据的统一封装，仅在文件首次被访问时动态创建对象实例，引用计数清零后自动释放。Vnode仅存在于主存中

5. 文件系统挂载：把文件系统安装到操作系统中
    1. 将某个设备上的文件系统挂载到目录后，就可通过该目录访问对应设备上的文件。此处的设备指逻辑上的设备，磁盘上的各个分区可视为多个独立设备
    2. Windows系统采用驱动器号(C、D盘)标识分区(也叫卷)，每个分区拥有独立的目录树，并关联一个已挂载到文件系统
    3. Unix系统以单一的根文件系统为基础，该文件系统在系统启动时由内核自动挂载。其他文件系统必须挂载到根文件系统中的某个目录下(挂载点)
    4. 同一设备(文件系统)可以被挂载到多个不同的挂载点，但同一挂载点在同一时刻只能挂载一个设备
