# 1.知识点
1. 文件的基本概念
    1. 文件的定义
        1. 文件是存储在计算机持久性存储设备(如磁盘)上的信息集合，其内容可以是文本、图像或其他形式的数据(**文件是一组有意义的信息的集合**)
        2. 用户在进行输入输出操作时，通常将文件作为逻辑操作的基本对象
        3. UNIX操作系统中，所有设备(含IO设备)都被视为特殊的文件
    2. 文件的属性

    5. 文件系统结构
        1. 文件系统是OS的核心子系统之一，**负责对存储设备上的文件和目录进行统一管理**，提供创建、读取、写入、删除和保护等基本操作。**向上**为用户和应用程序提供**抽象接口**；**向下**则与设备驱动协同，**高效调度物理存储资源**
            ![[Pasted image 20260704154605.png]]
            ![[Pasted image 20260704153910.png]]
        2. 文件系统层次结构图
            1. IO控制：包含设备驱动程序和中断处理程序，负责在内存与磁盘之间传输数据
            2. 基本文件系统：负责向设备驱动程序发送通用命令，以读写磁盘块；管理内存缓冲区，缓存文件系统元数据、目录项及数据块
            3. 文件组织模块：负责建立文件逻辑块与物理块之间的映射关系，将逻辑块地址转化为物理块地址；还包含空闲空间管理器，用于跟踪未分配的磁盘块，并按需分配给文件使用
            4. 逻辑文件系统：负责管理文件系统的元数据，不含实际数据内容。它维护目录结构，并根据给定文件名，向文件组织模块提供所需的元数据；同时通过FCB记录各文件的属性和状态，并负责实现文件保护机制
            ![[Pasted image 20260704154616.png]]
2. 文件的逻辑结构
    1. 文件的逻辑结构是指从用户视角看到的文件组织形式；而文件的物理结构(存储结构)则是指文件在外存上的实际存储方式，对用户透明
    2. 无结构文件、有结构文件
        1. 无结构文件：由连续的字符流构成，也称流式文件，**无明显的逻辑结构**。长度以字节为单位，访问时通过指针来定位下一个要操作的字节。系统中大量的源程序、可执行文件、库函数均采用无结构文件存储。**检索特定内容时只能进行顺序查找，效率低**
        2. 有结构文件：由一个或多个记录组成，也称记录式文件，每条记录由若干数据项组成
        ![[Pasted image 20260704152413.png]]
        ![[Pasted image 20260704153550.png]]
    3. 定长记录文件、变长记录文件：有结构文件按记录长度是否一致分类
        1. 定长记录文件：所有记录长度相同，且各数据项在记录中的位置固定
            ![[Pasted image 20260704162000.png]]
        2. 变长记录文件：各记录长度不一，数据项数量可以不同，数据项长度可变
            ![[Pasted image 20260704162046.png]]
    4. **顺序文件、索引文件、索引顺序文件、散列文件：有结构文件按记录组织形式分类**
        1. 顺序文件：记录按线性顺序依次排列，可采用定长或变长记录。根据记录是否按关键字排序，可以进一步分为串结构和顺序结构
            1. 考试题中的顺序文件指的是**物理上顺序存储**的顺序文件
            2. 只有物理上**顺序存储**的**定长记录顺序文件**可以实现**随机存取**第i个记录
                1. 若要快速找到某关键字对应的记录，就得用顺序结构
                ![[Pasted image 20260704162324.png]]
            3. 适用场景(优缺点)
                1. **顺序存储设备(如磁带)，只能按顺序文件进行组织**
                2. 顺序文件记录连续存储、访问局部性强，故**在批量处理场景下表现最优**。当需要连续读取或写入大量记录时，其IO效率在所有逻辑文件类型中最高
                3. 在频繁进行单条记录的增删改查时，由于缺乏直接定位能力且需要大量移动数据，性能不佳
            ![[Pasted image 20260704162237.png]]
        2. 索引文件：建立索引表以检索记录
            1. 建立一张索引表，为每个记录设置一个索引项，包含指向该记录的指针以及记录长度，并将索引项按关键字排序(根据关键字确定索引号)
            2. 索引表自身是由定长记录构成的顺序文件，支持高效随机访问，快速找到第i个索引项
            3. 优缺点
                1. 可以提高检索第i条记录的效率，主要用于**对信息处理的及时性要求比较高的场合**
                2. 每个记录对应一个索引表项，可能导致索引表庞大；索引表项可能比记录本身还大，导致存储利用率低下
            ![[Pasted image 20260704170553.png]]
        3. 索引顺序文件：顺序文件和索引文件的结合
            1. 先将变长记录的顺序文件划分为若干组，再为每组的首条记录建立一个索引项，包含该记录的关键字及其指针。所有索引项共同构成一张**按关键字有序排列的索引表**
            2. 记录组内可无序，组间必须按关键字有序
            3. 检索时，先在索引表中定位目标记录所属的组，然后在组内进行顺序查找
            4. 性能分析：索引表和记录组均采用顺序查找
                1. 可以建立多级索引以提升性能
                2. 严格来说：平均查找次数为$\frac{N+1}{2}$，但OS教材会直接忽略这个1
                ![[Pasted image 20260704191358.png]]
                ![[Pasted image 20260704190911.png]]
                ![[Pasted image 20260704191007.png]]
            ![[Pasted image 20260704190839.png]]
        4. 直接文件(散列文件)：记录的物理地址由关键字经过散列函数计算直接得到。支持极快的随机存取，但可能导致冲突
3. 文件目录结构
    1. 文件控制块(FCB)
        1. FCB是用于**存放控制文件所需的各种信息**的数据结构，以实现按名存取
        2. 每个文件对应一个FCB。每创建一个新文件，系统便为其建立一个FCB
        ![[Pasted image 20260705100248.png]]
        ![[Pasted image 20260705103415.png]]
    2. 文件目录(表)
        1. 所有FCB的集合构成文件目录(目录文件)
        2. **文件目录**是一种数据结构，用于记录每个文件的属性、存储位置等元数据，以便在检索时**快速定位文件在外存中的物理地址**
        3. 目录管理的要求
            ![[Pasted image 20260706230243.png]]
        ![[Pasted image 20260705103241.png]]
    3. **常见的目录结构**
        1. 单级目录结构：文件系统仅维护一张全局目录表，每个文件对应一个目录项
            ![[Pasted image 20260705105223.png]]
            ![[Pasted image 20260705133925.png]]
        2. 两级目录结构：文件目录划分为主文件目录和用户文件目录
            1. 允许不同用户的文件重名，但是不支持分类
            ![[Pasted image 20260705105535.png]]
        3. 树形(多级)目录结构：对两级目录结构进行推广，目前绝大多数OS采用
            1. 用户通过**文件路径名**来标识文件，路径名是一个用/分割的字符串
            2. 绝对路径：从根目录(/)开始的路径称为绝对路径，每个文件有唯一的绝对路径
            3. 相对路径：从当前目录出发到目标位置的路径称为相对路径
                1. 系统为每个进程设置一个当前目录(工作目录)，进程对文件的访问通常以当前目录为基准，可以减少磁盘IO次数(路径深度减少)
                2. 每个用户有自己的工作目录
            4. 优缺点
                1. 树形目录结构支持灵活的文件分类，层次清晰，便于管理和保护
                2. **查找一个文件**需要按路径名**逐级访问中间目录节点**，导致I/O次数增加，可能影响查询速度
                3. 不便于实现文件的共享
            ![[Pasted image 20260705105754.png]]
        4. 无环图目录：增加了开销，但是支持文件共享
            ![[Pasted image 20260705110717.png]]
    4. 索引节点：实现了对文件控制块的优化
        1. 引入原因+定义
            1. 如果文件数量庞大，那么对应FCB构成的文件目录也会非常庞大。存储该FCB需要多个磁盘块，系统进行查找时需逐块读入目录项，并逐一比对文件名，开销很大
            2. 然而，**系统在进行文件查找**(对比文件名)并确定物理地址时，**并不需要用到除文件名外的其他信息**，这些信息却作为FCB的表项被一并读入内存
            3. UNIX等系统采用**文件名与描述信息分离**的设计策略，将文件的描述信息独立组织到索引节点中(inode、i节点)，**目录项仅由文件名+索引节点号**(索引节点指针)组成
                ![[Pasted image 20260705135926.png]]
                ![[Pasted image 20260705135933.png]]
                ![[Pasted image 20260705103809.png]]
        2. 效率分析：由于FCB的体积变小，单个磁盘块可以容纳更多的FCB，从而降低了磁盘IO次数。**这里的磁盘块查找默认顺序查找**
            ![[Pasted image 20260705104035.png]]
            ![[Pasted image 20260705110940.png]]
        3. 索引节点分为磁盘索引节点和内存索引节点
            1. 磁盘索引节点存储在磁盘上，每个文件有唯一的磁盘索引节点
            2. **内存索引节点=磁盘索引节点+运行时状态信息**

4. **文件的物理结构**(文件分配方式)
    1. 基本定义
        1. 文件分配方式：研究文件数据如何分布在**已分配**给它的物理块上，以及这些块之间如何组织，属于对非空闲块的管理。文件分配方式直接决定文件的物理结构，这两个词常常混用
        2. 磁盘被划分为若干磁盘块，其大小通常与内存页面一致。所有磁盘IO操作均以块为单位，在内存与磁盘之间进行数据交换
        3. 文件的逻辑地址空间也被分为若干文件块，其逻辑地址可以表示为(逻辑块号，块内地址)
        ![[Pasted image 20260705143405.png]]
    2. 连续分配
        1. 每个文件在磁盘上占有一组连续的块，其逻辑块依次存放在相邻的物理块中
        2. 文件的目录项需要记录该文件起始块的块号及其所占用的总块数
        3. 优缺点
            1. 由于磁盘地址本身具有线性顺序，这种布局使得进程访问文件时所需的寻道次数和寻道时间最小
            2. 物理块号=起始块号+逻辑块号，可以直接求出物理块号，实现直接访问(随机访问)；也可以逐块往后读，即顺序访问
                ![[Pasted image 20260705150443.png]]
                ![[Pasted image 20260705151332.png]]
            3. 不方便扩展：如果A想要扩展为占四个块，则只能整体迁移到下面
                ![[Pasted image 20260705151743.png]]
            4. 会产生外部碎片：类似于动态分区分配
            ![[Pasted image 20260705150353.png]]
            ![[Pasted image 20260705150403.png]]
        ![[Pasted image 20260705144538.png]]
    3. 链接分配
        ![[Pasted image 20260705162012.png]]
        1. 隐式链接(考试默认情况)：当前盘块存储指向下一个盘块的指针
            ![[Pasted image 20260705162224.png]]
            ![[Pasted image 20260705162417.png]]
            ![[Pasted image 20260705162636.png]]
        2. 显式链接：把用于链接文件各物理块的指针集中存放在内存的一张全局表中
            1. 该表在整个文件系统中仅设一张，称为文件分配表(FAT)。开机时，将FAT从磁盘读入内存，此后常驻内存
            2. FAT的每个表项对应一个磁盘块，并存放指向下一块的指针
            3. 文件目录项只需要记录该文件的起始块号，就可以通过查询FAT得到后续所有块号，而无需磁盘IO
            4. 通常，用$-1$标记文件的最后一块，用$-2$标识空闲盘块。从而，FAT不仅记录了文件的链式结构，还标识了空闲盘块，系统可直接利用FAT管理磁盘的空闲空间

            2. 索引表存放的磁盘块称为索引块，文件数据存放的磁盘块称为数据块
            3. 目录项中记录文件的索引块对应的物理块号

        1. 文件很大时，使用盘块多，对应的索引表无法装在一个磁盘块中，因此要拆成多个索引块。为这些索引块再建立一级索引，称为主索引(一级索引)

            1. 小文件：全部盘块地址直接存放在inode/FCB中，系统直接从中获取所有盘块地址，无需读取索引结构(直接寻址)
            2. 中型文件：采用单级索引分配，inode中存放索引块地址(一次间址)

5. 文件的基本操作
    1. 创建文件(create系统调用)：合法性检验->分配索引节点->**分配磁盘块**->**新建目录项**->更新文件系统元数据->(打开并返回文件描述符)
        ![[Pasted image 20260706130256.png]]
        ![[Pasted image 20260706130520.png]]
    2. 删除文件(delete系统调用)：**定位文件目录项**->检查文件使用状态->**移除目录项**->释放索引节点->**释放磁盘块**->(释放内存临时资源)->更新文件系统元数据
        ![[Pasted image 20260706131044.png]]
        ![[Pasted image 20260706131155.png]]
    3. **打开文件**(open系统调用)：**定位文件目录项**->**若第一次打开该文件，则读取索引节点到内存**->**更新两张打开文件表**
        1. 两张打开文件表
            1. 系统维护一张**系统打开文件表**：该表全局共享，存储与进程无关的文件属性：磁盘位置、文件大小等。每个表项包含一个**打开计数器**，记录打开该文件的进程数
                1. 用于访问打开文件表的索引号，称为文件描述符/文件句柄。open()执行成功后，**后续所有文件操作均使用文件描述符进行**
                2. 打开文件表中不需要记录文件名
            2. 每个进程有一张**进程打开文件表**：记录进程私有的访问状态，如当前读/写指针位置、访问权限，文件打开模式等。**该表中的每一项均指向系统打开文件表的对应项**
            ![[Pasted image 20260706132042.png]]
            ![[Pasted image 20260706133518.png]]
        2. 系统根据文件路径定位目录项，并把关键信息载入内存(**打开文件时并不会直接读入文件数据**)，**在两张打开文件表中创建对应表项**，并**将进程已打开文件表中对应表项的文件描述符**返回给用户
        3. **用户再次操作文件时，只需要提供文件描述符**，系统即可直接从内存获取所需信息，显著降低目录检索开销
        ![[Pasted image 20260706132557.png]]
        ![[Pasted image 20260706132031.png]]
    4. 关闭文件(close系统调用)：从进程的打开文件表中删除对应项->打开计数器减1->计数为0时删去文件在系统表中的项，释放相关资源

6. 文件共享
    1. 文件共享允许多个用户访问同一文件，系统中仅需保留一个物理副本
    2. 基于索引节点的共享方式(硬链接)
        1. 两个用户目录中的文件名称可以不同，但指向同一个索引节点
        2. count = 0时：系统才能真正删除文件，释放其索引节点及相关资源
        ![[Pasted image 20260706135538.png]]
        ![[Pasted image 20260706135726.png]]
    3. 基于符号链接的共享方式(软链接)(类似Windows快捷方式)
        1. 创建一个**LINK类型**的新文件L，文件L中包含目标共享文件的路径名
        2. 用户访问L时，OS识别出其LINK类型，并根据其中记录的路径逐级查找目录，定位到目标文件，并执行读写
        3. 系统可以直接删除共享文件的索引节点。共享文件被删除后，LINK文件依然存在，只是失效
        4. 使用软链接时，每次访问共享文件都需要逐渐遍历目录，开销大；符号链接L本身也是个文件，有索引节点，需要占据一定空间。访问速度比硬链接慢
        5. 可用于实现网络文件共享：记录文件所在机器的网络地址+文件路径名

7. 文件保护
    1. 口令和加密用于防止他人非法获取文件内容，不区分具体的访问操作类型；访问控制则用于精细管理用户对文件的具体访问权限
    2. 口令保护：用户在创建文件时设置一个口令，系统将口令存入FCB，访问者访问该文件时需要提供正确口令
        1. 时空开销小：口令存储在FCB中，存储开销低；用户访问文件时，系统直接读对应口令并进行对比即可，时间开销低
        2. 安全性较低：口令常以**明文或弱保护**形式存放在系统中，一旦系统被攻陷，则文件全部泄露
        ![[Pasted image 20260706170413.png]]
    3. 密码保护：用户使用密码对文件内容进行加密，访问时需要使用密码解密
        1. 保密性强：系统中只存放密文，不存放密码
        2. 加解密过程会引入一定的计算开销
        3. 使用错误密码会得到乱码，但是系统会进行拦截，不显示
        ![[Pasted image 20260706170945.png]]
        ![[Pasted image 20260706171010.png]]
    4. 访问控制：基于用户身份进行权限管理
        1. 访问类型
            ![[Pasted image 20260706171507.png]]
        2. 为每个文件和目录附加一个访问控制列表(ACL)，明确指定各用户名及其被允许的访问类型(**用户及其可以执行的操作**)
            1. 优点：支持灵活而复杂的访问策略
            2. 缺点：列表长度不可预知，可能带来复杂的空间管理开销
            ![[Pasted image 20260706224954.png]]
        3. 为降低开销，现代系统常采用精简的访问控制列表(按用户类别统一管理权限)
            1. 系统管理每个类别用户拥有的权限
            2. 当用户访问文件时，系统按优先级顺序匹配其身份：若为拥有者，则赋予拥有者权限；若与拥有者所属同一组，则赋予组权限；否则赋予其他权限
            ![[Pasted image 20260706225320.png]]
            ![[Pasted image 20260706225636.png]]
        4. 如果对某个目录进行了访问权限控制，那要对目录下的所有文件进行相同的访问权限控制
